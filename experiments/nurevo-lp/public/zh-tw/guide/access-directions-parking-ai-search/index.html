如何撰寫交通資訊與停車頁面，讓 AI 搜尋給出正確答案

要讓 AI 給出正確的交通與停車資訊，請在交通資訊頁上以 HTML 文字寫明以下內容，而不是只放地圖或圖片：完整地址（包括室號或樓層）、最近的車站或站牌及出口與步行時間（以及測量方式）、到入口為止的地標，以及停車資訊（有無、車位數、位置、費用）。接著在所有地方使用同一種地址寫法——你的網站、Google 商家檔案與各類店家目錄網站——並在結構化資料中放入相同的地址與入口的座標。如果沒有停車場，也要直接寫明：「本店沒有停車場，請使用 Example Street 上的公有停車場。」這樣 AI 就比較沒有猜測的空間。

撰寫於 2026 年 11 月 21 日（日本時間）。營業時間請見如何公布營業時間與公休日，預約請見如何撰寫預約頁面。本指南適用於所有需要顧客到訪的店家——店鋪、診所、工作室、辦公室、民宿——只聚焦一件事：讓 AI 正確說出怎麼到你這裡，以及能不能開車來。

AI 的回答會因日期、提問措辭與服務而改變。這裡的步驟能讓 AI 比較不容易誤讀你的交通資訊，並告訴你如何檢查；但不保證你會出現在回答中，也不保證回答一定正確。

交通資訊頁上應寫的八項內容

把這些內容放在據點頁面或獨立的「交通資訊」頁面上。即使嵌入了地圖，也要用文字寫出同樣的資訊：AI 可能無法讀取地圖裡的內容。

要寫的內容範例不寫會發生的問題
包含室號或樓層與郵遞區號的完整地址123 Example Street, Suite 300, Springfield, IL 62701缺少室號的地址四處流傳，顧客到了門口卻找不到

不好的寫法：「近車站！有停車場。請看地圖。」好的寫法：「從 Springfield 站北出口步行 4 分鐘（約 300 公尺）。123 Example Street, Suite 300。入口在大樓左側的通道裡。大樓後方有兩個專用車位（7 號與 8 號）；車位已滿時，請使用 Oak Street 上的公有停車場。」

只寫「有停車場」，並沒有說明有幾個車位、在哪裡、是否免費，或是否為特約停車場。如果是特約停車場，請寫出它的名稱、地址與折抵條件（例如「消費滿 $20 可免費停車一小時」）。條件變更時，當天就更新頁面。

步行時間：決定測量方式，並寫出來

步行時間很容易前後不一致。日本的不動產廣告有固定規則：依沿途道路距離計算，每分鐘 80 公尺，不足一分鐘的部分進位為一分鐘，不考慮紅綠燈或坡道（日本不動產廣告公平競爭規約的施行規則，參見三菱地所 House Net 的用語解說，日文）。店鋪與診所不受此約束，其他國家也沒有共通規則，但選定一種規則並持續使用，就能避免你的網站與目錄網站上的資訊互相矛盾。

  1. 決定起點與終點（「從北出口剪票口到本大樓入口」）
  2. 在地圖 App 中測量沿路線的步行距離，再依你的規則換算。同時寫上距離（「約 300 公尺」），AI 和人都能核對
  3. 在有多個出口的大型車站，寫明最近的出口，並為從其他出口出來的人補充一句說明
  4. 檢查目錄網站與 Google 商家檔案的簡介是否寫著不同的數字，並加以統一

只有真的就在出口旁邊，才寫「離車站 1 分鐘」。誇大的步行時間會在評論中被指出與實際不符。

所有地方使用同一種地址寫法

一般認為，AI 服務會綜合你的網站、Google 商家檔案、目錄網站與社群媒體檔案，來判斷它們是否指同一家店家；具體如何比對並未公開。各平台上的地址寫法不同時，這些資訊可能無法連結起來，或者缺少室號或樓層的地址會出現在回答中。請決定以下五點，並在所有平台上統一使用。

  1. 縮寫：用「Street」還是「St」，用「Suite」還是「Ste」。哪種都可以，選定一種
  2. 字元：使用一般連字號，編號方式保持一致，不使用裝飾性符號
  3. 大樓名稱、室號與樓層。如果大樓改名，當天就更新所有平台
  4. 是否寫州或地區（結構化資料中一定要寫）
  5. 如果也公布其他語言的地址，要寫得讓人看得出是同一個地方（包含大樓名稱）

搬遷後，在交通資訊頁上寫明新地址，並加上一句「我們已於（日期）搬遷；舊地址為……」。如果只是刪除舊頁面，其他網站上的舊地址就會與你的網站失去連結，AI 可能會繼續給出舊地址。

在 Google 商家檔案中設定停車與無障礙屬性

Google 商家檔案中有「屬性」，會顯示在 Google 搜尋、Google 地圖與其他 Google 服務上。有些屬性由你自行編輯，有些則可能依到訪顧客的回饋填入。無障礙屬性包括輪椅可通行的入口、洗手間、座位、電梯與輪椅可用的停車位——如果你有專供無障礙需求人士使用的車位，最後一項請選擇「是」。Google 表示，編輯內容的審查通常約需 10 分鐘，但最長可能需要 30 天（管理商家屬性，2026 年 11 月 21 日查閱）。你能看到哪些屬性，取決於商家類別。

Google 的 AI Overviews 與 AI Mode 如何使用商家檔案的屬性並未公開。但商家檔案就是 Google 地圖與搜尋中顯示的資訊，所以要讓它與你的網站內容一致。屬性無法表達的細節——車位數、費用、特約條件——請寫在頁面內文與商家檔案的簡介中。

結構化資料：地址、座標、地圖與設施

在 Google 的 LocalBusiness 結構化資料文件（2026 年 9 月更新）中，name 與 address 為必要屬性，geo（緯度與經度）為建議屬性。範例將地址拆成 PostalAddress 的 streetAddress、addressLocality、addressRegion、postalCode 與 addressCountry，座標的精確度至少要到小數點後五位。請在地圖 App 中取入口位置的座標：對交通資訊來說，人們實際使用的那扇門比大樓中心點更有用。

Google 的文件沒有提到，但 schema.org 還有 hasMap（指向該地點地圖的 URL）、amenityFeature（以 LocationFeatureSpecification 的 name/value 形式寫出的設施）與 publicAccess（該地點是否對大眾開放）。在我們的調查中，沒有找到 Google 或任何其他 AI 服務使用 hasMap 或 amenityFeature 的官方說明。加上它們沒有壞處，但應把它們視為頁面內文既有內容的重述。

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Dentist",
  "@id": "https://example.com/#business",
  "name": "Example Dental",
  "url": "https://example.com/",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "123 Example Street, Suite 300",
    "addressLocality": "Springfield",
    "addressRegion": "IL",
    "postalCode": "62701",
    "addressCountry": "US"
  },
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 39.79817,
    "longitude": -89.64407
  },
  "hasMap": "https://example.com/directions/",
  "amenityFeature": [
    { "@type": "LocationFeatureSpecification", "name": "Free patient parking (2 spaces)", "value": true },
    { "@type": "LocationFeatureSpecification", "name": "Elevator", "value": true }
  ]
}
</script>
<!-- Coordinates and counts are examples. Take your own entrance's coordinates from a
     map app and use the same values as the page text -->

結構化資料中的地址、座標與車位數必須與頁面內文一致。請用複合式搜尋結果測試或 Schema Markup Validator 檢查語法。如果有多個據點，請為每個據點建立獨立頁面，並分別寫上各自的地址與座標（請見多據點店家的 AI 搜尋）。

WordPress 步驟（使用 Nurevo AIO）

在 Nurevo AIO（免費，舊顯示名稱為 Nurevo AEO）中，你在「地址」欄位輸入的內容會原樣發布到商家結構化資料（PostalAddress 的 streetAddress）與 llms.txt 的「Address」行。請依以下順序操作。

  1. 先依上面的八項內容修改交通資訊頁的內文（頁面內文優先於結構化資料）
  2. 在「地址」欄位中使用與頁面和 Google 商家檔案相同的寫法，包括室號、樓層與郵遞區號。此欄位會以單一字串發布，不會拆開
  3. Nurevo 不會從地址推測座標。若要發布座標，請用開發者篩選器 webmcp_canary_business_node 加入 geo（程式碼如下）；hasMap 與 amenityFeature 也能用同樣方式加入
  4. 如果你的 SEO 外掛或佈景主題已經發布了商家名稱、地址、電話與營業時間，Nurevo 不會再發布第二個商家節點，因此篩選器不會生效；請改在該外掛或佈景主題中加入座標。Nurevo 不會與 Yoast SEO、Rank Math、All in One SEO 或 Slim SEO 重複輸出，自 0.9.1 起也能與 SEO SIMPLE PACK 及 VK All in One Expansion Unit 並用
  5. 外掛診斷中的「關鍵資訊涵蓋率」項目會顯示名稱、地址、電話、營業時間、位置與 URL 是否都已發布
  6. 設定為網路商店或 B2B 網站的站點不會發布營業時間與位置（geo），因為沒有可供到訪的地點
add_filter('webmcp_canary_business_node', function ($org, $settings) {
    // Entrance coordinates and the directions page. Same values as the page text
    $org['geo'] = array(
        '@type'     => 'GeoCoordinates',
        'latitude'  => 39.79817,
        'longitude' => -89.64407,
    );
    $org['hasMap'] = home_url('/directions/');
    $org['amenityFeature'] = array(
        array('@type' => 'LocationFeatureSpecification', 'name' => 'Free patient parking (2 spaces)', 'value' => true),
    );
    return $org;
}, 10, 2);

把它加到子佈景主題的 functions.php 或程式碼片段外掛中，然後查看頁面原始碼或使用複合式搜尋結果測試，確認商家資訊中出現了 geo。搬遷或停車安排變更時，請在同一天更新欄位、篩選器與頁面內文。

負責維護客戶網站的代理商，可以把「當天更新所有平台」列為搬遷、停車合約變更與大樓改名時的標準作業。Nurevo 為提供每月維護支援的代理商設有合作夥伴計畫。

修改後如何檢查

在修改當天以及兩到四週後，向 AI 提出相同的問題，並記錄回答。沒有任何 AI 服務公開資訊更新需要多久。

問題正確的回答
「（店家）的地址是什麼？」包含室號或樓層的現址，而不是舊地址
「從（車站）怎麼去（店家）？」你網站上寫的出口與步行時間
「（店家）有停車場嗎？」與你網站一致的有無停車場、車位數與特約條件
「（店家）方便輪椅進出嗎？」與你的網站及 Google 商家檔案一致
「（地區）有停車場的（業種）」你的名字是否出現，以及你的交通資訊頁是否被引用

記錄日期、AI 服務、問題、回答與被引用的 URL。如果來源是目錄網站或舊傳單，就去修正它。在 Nurevo 的 Free 與 Standard 方案中，Nurevo 服務每月一次依你的業種與地區產生三個不含品牌名稱的問題詢問 Perplexity，並顯示你的名字是否出現、網站是否被引用。Pro（Beta 版，每月 USD 99 起）可在 Perplexity 上追蹤最多 20 個問題（ChatGPT 設定完成後也將支援）。停車與交通相關的問題請手動記錄。請見如何衡量 AI 能見度。

發布前檢查清單

  1. 包含室號或樓層與郵遞區號的地址已用 HTML 文字寫出
  2. 已寫出最近的車站或站牌、路線、出口、步行時間與距離，並決定了測量的起點與終點
  3. 已寫出附兩三個地標的路線，以及入口與樓層
  4. 已寫出停車資訊——有無、車位數、位置、費用、特約條件；如果沒有停車場，也已寫明
  5. 已說明自行車、機車、無障礙與嬰兒車的相關資訊
  6. 網站、Google 商家檔案、目錄網站與社群媒體檔案上的地址寫法一致
  7. Google 商家檔案的屬性（停車、無障礙）與網站一致
  8. 結構化資料中的地址與座標（至少到小數點後五位）與頁面內文一致
  9. 沒有任何頁面、PDF 或部落格文章仍顯示舊地址或已不再使用的停車場
  10. 已決定要問的問題，並記錄了修改當天與兩到四週後 AI 的回答

常見問題

我們嵌入了地圖。還需要用文字寫交通資訊嗎？

需要。AI 能否讀取嵌入的地圖或交通資訊圖片，依服務而異，而且並未公開。把地圖當作給人看的輔助，在頁面內文中寫出車站、出口、步行時間、入口與停車資訊。

我們沒有停車場。乾脆不寫可以嗎？

寫明「本店沒有停車場」比較保險。如果什麼都不寫，AI 可能會根據其他網站回答或自行猜測。請補充附近可以停車的地方，以及搭乘大眾運輸前來的方式。

步行時間該怎麼計算？

沒有通用的規則。日本不動產廣告的標準（依道路距離、每分鐘 80 公尺、不足一分鐘進位）是一個清楚的選項。無論選擇哪種方式，都要寫明從哪裡量到哪裡，並加上距離。

要出現在 AI 回答中，結構化資料裡一定要有座標嗎？

不一定。在 Google 的文件中，geo 是建議屬性，只有 name 與 address 是必要的。ChatGPT 或 Perplexity 是否使用座標並未公開。請先修正頁面內文與地址寫法，再加入在入口處取得的座標。

應該加入 hasMap 或 amenityFeature 嗎？

可以加入，但它們不在 Google 的文件中，我們也沒有找到任何 AI 服務使用它們的官方說明。請把它們當作頁面上既有的地圖頁面與停車資訊的重述來加入。

我們搬遷了，但 AI 一直給出舊地址。

在同一天更新網站、Google 商家檔案、目錄網站與社群媒體檔案，並在交通資訊頁上保留一行寫明搬遷日期與舊地址的說明。檢查 AI 引用的 URL；如果是舊頁面或 PDF，請修正或刪除。更新所需時間並未公開，所以幾週後再問一次。

Nurevo 的「地址」欄位可以寫室號與樓層嗎？

可以，請務必寫上。此欄位會原樣發布到 streetAddress 與 llms.txt 的「Address」行。請使用與頁面及 Google 商家檔案相同的寫法。

看看 AI 能否讀懂你的網站
