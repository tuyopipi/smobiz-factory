Is Cloudflare or a WAF blocking AI crawlers? How agencies check each layer and set it up

When a client's site is not cited by ChatGPT or Perplexity, look past robots.txt: check whether a CDN such as Cloudflare, the host's firewall (WAF) or a security plugin is returning 403 or 429 to AI search crawlers. If a request is stopped before it reaches the site, allowing the crawler in robots.txt changes nothing. On 1 July 2026 Cloudflare gave every plan, including Free, separate controls for Search, Agent and Training crawlers, and domains added from 15 September 2026 block Training and Agent bots on pages that show ads by default. This guide walks through the four layers to check, how to explain the choice to the client, and what to add to a care plan.

Written 22 November 2026 (JST). For web agencies, WordPress care companies and freelancers who manage a client's hosting or CDN. Cloudflare screen names follow its documentation at the time of writing; screens change, so check each linked page before you work.

AI answers change by day and wording. Letting crawlers in is a precondition for being read and cited, not a guarantee of appearing in AI answers.

The four layers where AI crawlers get stopped

A crawler's request passes through the CDN, then the server, then WordPress. If any one layer stops it, settings further along (such as an allow rule in robots.txt) never come into play. The status code also differs by layer.

One report describes a managed WordPress host returning 429 to AI crawlers only for pages not in cache, which the WAF dashboards did not show ([Search Engine Land](https://searchengineland.com/managed-wordpress-blocking-ai-bots-476510), a single-site case).

On how common this is: an agency founder writing on HackerNoon checked 640 hand-picked sites; of 591 that could be measured, 100 refused GPTBot or ClaudeBot, and only 4 of those said so in robots.txt (HackerNoon, 19 Nov 2026; the author notes the sample is not random). It is a useful reminder that some blocking never shows up in robots.txt.

Cloudflare's 2026 changes: how the settings work now

For clients on Cloudflare, the model changed in 2026. Older guides that only say to turn off "Block AI bots" may not match today's screens.

The settings live in the domain's (zone's) Security Settings, according to Cloudflare's documentation.
WhenWhat changedSource
1 July 2026Controls for AI crawlers split into Search, Agent and Training, for all customers including Free. For each you can block on all pages, block only on pages that display ads, or not blockCloudflare changelog
From 15 September 2026New domains onboarding to Cloudflare block bots classified as Training or Agent on pages that display ads; Search stays allowedCloudflare changelog
15 September 2026Training gains a "Disallow AI Training" option (ask not to train, without blocking). The single "Block AI Bots" toggle is to be retired. Managed robots.txt becomes Bot Preference SyncCloudflare blog, Impress Watch

Cloudflare defines the three behaviours like this: Search collects or indexes content so it can answer questions later; Agent acts in real time on a person's behalf, such as chat fetch bots and browser-use agents; Training crawls content to train or fine-tune a model (Cloudflare: bot concepts).

Cloudflare's verified bots page gives OAI-SearchBot as an example of the older "AI Search" category, now treated as Search, and Perplexity-User as an example of "AI Assistant" (Cloudflare: verified bots). The pages we read did not list the category of each crawler, such as ChatGPT-User, Claude-SearchBot or PerplexityBot, so check the list in the client's AI Crawl Control screen.

Take care with Training. At the July launch, Cloudflare said blocking Training would also affect multi-purpose crawlers that combine search and training (Cloudflare changelog); Help Net Security named Googlebot, Applebot and Bingbot as examples (Help Net Security). When a client does not want content used for training, "Disallow AI Training" is an alternative to blocking (Cloudflare blog). Either way, check Googlebot's responses after the change.

The check: go through the four layers

Run these commands against the client's home page and the pages you most want cited (pricing, services, FAQ). If step 1 returns 200 for the browser but 403, 429 or 503 for AI crawler names, some layer is filtering by user agent. If the headers in step 2 include cf-ray, the site is behind Cloudflare.

# 1) Compare status codes for the same URL with different user agents
URL="https://example.com/"
for UA in \
  "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/130 Safari/537.36" \
  "OAI-SearchBot/1.0" "ChatGPT-User/1.0" \
  "PerplexityBot/1.0" "Perplexity-User/1.0" \
  "Claude-SearchBot/1.0" "Claude-User/1.0" \
  "GPTBot/1.0" "ClaudeBot/1.0"; do
  printf '%-22.22s ' "$UA"
  curl -s -o /dev/null -w '%{http_code}\n' -A "$UA" "$URL"
done

# 2) Clues to which layer answered (CDN, server)
curl -sI "$URL" | grep -iE '^(server|cf-ray|cf-cache-status|x-powered-by|via):'

# 3) The robots.txt actually served (including lines a CDN prepends)
curl -s "$URL"robots.txt | head -60

# 4) Count status codes returned to the real crawlers in the server log
#    (combined log format, status code in column 9)
grep -E 'OAI-SearchBot|ChatGPT-User|PerplexityBot|Perplexity-User|Claude-SearchBot|Claude-User' access.log \
  | awk '{print $9}' | sort | uniq -c

Treat step 1 as a clue only. Real crawlers come from the IP addresses each company publishes (OpenAI: crawlers, Perplexity: crawlers). A request from your own machine that only borrows the name may be blocked as an impostor, or the opposite: only the real crawler may be blocked. On Cloudflare's Free plan, AI Crawl Control identifies AI crawlers by user agent string; paid plans can also use Bot Management detection (Cloudflare: manage AI crawlers).

So finish with step 4 or the CDN's logs to see what the real crawlers received. Cached pages can return 200 while uncached ones are blocked (Search Engine Land), so test recently updated pages as well as the home page.

Checking and setting Cloudflare

  1. In the domain's Security Settings, filter by Bot traffic and open "AI Crawler and Agent access policies" to see the Search, Agent and Training settings. Change them if they do not match the client's policy (Cloudflare: managed robots.txt).
  2. In AI Crawl Control, the Crawlers tab shows each crawler's category, requests (allowed and unsuccessful), robots.txt violations and action. The docs note that unsuccessful requests can come from any rule or error, not only the block action (Cloudflare: manage AI crawlers).
  3. Choosing Block in AI Crawl Control creates or updates a WAF custom rule on the zone (same page). Review the custom rules for anything touching AI crawlers, with who created it and when.
  4. With Bot Preference Sync on and at least one policy set to block or disallow training, Cloudflare prepends lines to robots.txt, including a Content-signal line and Disallow rules for GPTBot, ClaudeBot, Google-Extended and others (Cloudflare: managed robots.txt). That explains why the served robots.txt can differ from the one WordPress writes, so read the final file with curl.
  5. If bot protection features such as Bot Fight Mode are on, check their settings and events too. We could not confirm in Cloudflare's docs at the time of writing how verified bots are treated there, so check the event log for real blocks.

Checking the host and plugins

  1. In the host's control panel, check WAF, bot protection, country restrictions and rate limits, and their logs. If there are no logs, ask support, giving the time and user agent.
  2. Some managed WordPress hosts throttle in ways customers cannot switch off. In the case above, the host's support explained the mechanism (Search Engine Land).
  3. Look for OAI-SearchBot, PerplexityBot and similar names in your security plugin's block log. If it blocks by a user-agent list, make sure only training crawlers are on it.
  4. Check that no caching plugin or server cache serves bots a different page. The safe default is the same HTML for everyone.
  5. We found no official statement of how each hosting company's WAF treats AI crawlers, so check each host with the steps above and its access logs.

Explaining it to the client: the policy is theirs

Whether to let AI crawlers in is a business decision for the client. Agencies avoid later disputes by explaining the options and what each one does, then confirming the settings match the decision.

WordPress steps (with Nurevo AEO)

With the free Nurevo AEO plugin, the robots.txt layer works as follows. The CDN, host and plugin layers sit outside Nurevo AEO, so check them separately with the steps above.

  1. It allows the crawlers AI search uses (OAI-SearchBot and ChatGPT-User, Claude-SearchBot and Claude-User, PerplexityBot and Perplexity-User) in robots.txt. Your existing rules, such as Disallow: /wp-admin/, still apply to them.
  2. Training crawlers (GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, CCBot) are left to your robots.txt by default, with a one-click allow or block. Blocking them does not affect AI search or the AEO score.
  3. The Nurevo service never switches robots.txt to Disallow on its own. Suggestions appear in wp-admin and apply only when you press Apply.
  4. The AEO diagnosis fetches the public home page, /robots.txt and /llms.txt. A clean robots.txt result does not rule out a CDN or WAF block, so pair it with the curl and log checks in this guide.
  5. If Cloudflare's Bot Preference Sync is on, Cloudflare's lines come before the robots.txt WordPress serves. Check the public /robots.txt for contradictions between the two.
  6. For developers, filters can change the lists of search and training crawlers (named in the plugin's developer notes).

Audit checklist

  1. The client's policy for search, agent and training crawlers is confirmed in writing.
  2. The public /robots.txt does not disallow AI search crawlers.
  3. If a CDN adds lines to robots.txt, you have read them.
  4. Status codes for a browser and AI search crawler names match on key pages.
  5. Response headers show whether the site is behind a CDN.
  6. The CDN's three categories match the client's policy.
  7. Googlebot's responses did not change after training was restricted.
  8. WAF custom rules and bot protection events show no unintended AI crawler blocks.
  9. Host and security plugin logs show no blocks of AI search crawlers.
  10. Access logs show 200 responses to the real crawlers.

FAQ

If robots.txt allows the crawlers, can I skip the CDN settings?

No. robots.txt is a rule crawlers read for themselves; a CDN or WAF stops requests before that. If the CDN blocks them, the pages go unread whatever robots.txt says. Check both.

Does the 15 September default apply to clients who have used Cloudflare for years?

Cloudflare's changelog says the 15 September defaults apply to newly onboarded domains. Older "Block AI bots" settings or WAF rules someone created may still be in place, so check existing domains too.

If we block GPTBot, will the site drop out of ChatGPT search?

GPTBot is OpenAI's training crawler; ChatGPT search uses OAI-SearchBot. Blocking the training crawler has no direct bearing on citations in search. Check which of the two is blocked.

curl with an AI crawler name returned 200. Are we fine?

It is a clue, not proof. Real crawlers come from each company's IP addresses, so bot protection that checks IPs can treat them differently. Confirm the real responses in the access log or CDN logs.

We saw 429 responses. What does that mean?

429 means too many requests, usually a rate limit at the host or CDN. Because it is throttling rather than a block rule, it may not appear in the WAF dashboard. Ask the host, giving the time and user agent.

The client wants AI to read nothing at all.

It is their decision, so set it up that way. It helps to explain in writing that their pages become less likely to be cited in ChatGPT or Perplexity answers, and that declining training alone is also an option.

If we let the crawlers in, will the client appear in AI answers?

That cannot be guaranteed. Access is a precondition for being read. AI answers change by day and wording, and also depend on whether facts such as prices, areas and results are on the pages.
