Do AI crawlers run JavaScript? How to check what ChatGPT and Perplexity actually see on your site

Plan as if ChatGPT, Claude and Perplexity read only the initial HTML of your page, the text the server sends before any JavaScript runs. Vercel's 2024 analysis and several tests run in 2026 found that these crawlers and assistants did not execute JavaScript. Google (AI Overviews, AI Mode) processes JavaScript through its search pipeline, but if you want other AI tools to quote your prices, hours, service area or FAQ answers, put those facts in the initial HTML as plain text. This guide shows how to check, and where WordPress sites tend to bury facts behind JavaScript.

Written 26 November 2026 (JST). It is for people who run their own site and for agencies that build or maintain sites. The commands run in a terminal, and there are also checks that need no commands.

AI companies change their systems without notice, and the tests quoted here each capture one moment. AI answers also vary by day and wording. Getting your facts into the initial HTML is a precondition for being read, not a guarantee of appearing in AI answers.

The answer: which AI tools run JavaScript (as far as is known)

First, the initial HTML is the text your server sends first. A browser then runs JavaScript to load lists, embed reviews, draw maps and so on. A crawler that does not execute JavaScript never sees what was added afterwards.

OpenAI and Perplexity publish their crawler names and purposes (OpenAI: crawlers, Perplexity: crawlers). As Uravation notes, these pages describe purposes rather than promising anything about JavaScript (Uravation), so actual behaviour has to be inferred from outside measurements and tests.

Google says in its guide to generative AI features that it processes JavaScript unless it is blocked (Google: Optimizing your website for generative AI features, 10 July 2026), and Google Search handles JavaScript through crawling, rendering and indexing (Google: JavaScript SEO basics). Pages in Google's index can therefore be read after JavaScript has run. Do not expect the same from ChatGPT, Claude or Perplexity.

Check 1: look at the initial HTML from the command line

The most reliable check is to save the HTML your server sends first and search it for the facts you want AI to quote. curl does not run JavaScript, so it sees roughly what a non-rendering crawler sees. Try it on the pages you most want cited: pricing, services, FAQ, location.

# 1) Save the HTML the server returns first (before any JavaScript runs)
URL="https://example.com/pricing/"
curl -sS -L --compressed -o initial.html \
  -w 'status=%{http_code} final=%{url_effective}\n' "$URL"

# 2) Are the facts you want AI to quote present as text in that HTML?
for WORD in '$49' 'Closed Tuesdays' '555-0134' 'Free parking'; do
  if grep -qF "$WORD" initial.html; then echo "found    $WORD"; else echo "MISSING  $WORD"; fi
done

# 3) Is structured data (JSON-LD) in the initial HTML? (0 means no)
grep -o 'application/ld+json' initial.html | wc -l

# 4) Does the same fact come back when you send an AI crawler's name? (a clue only)
for UA in "ChatGPT-User/1.0" "OAI-SearchBot/1.0" "Claude-User/1.0" "PerplexityBot/1.0"; do
  printf '%-20s ' "$UA"
  curl -sS -L --compressed -A "$UA" "$URL" | grep -cF '$49'
done

Anything step 2 reports as MISSING is added by JavaScript, sits inside an image, or lives on another page. If a number is split by tags such as <span>, search for a shorter piece (just "49", for example).

Step 4 is only a clue. A request that merely uses a crawler's name comes from a different IP address than the real crawler, so the host or CDN may treat it differently. If it returns 403 or different content, check the bot-protection layers (how to check whether a CDN or WAF blocks AI crawlers).

Check 2: without the command line

  1. View the source: in Chrome, right-click and choose "View page source" (Ctrl+U on Windows, Option+Command+U on Mac), then search with Ctrl+F (Command+F) for your price or phone number. This is the initial HTML. The "Inspect" panel shows the page after JavaScript, so it is not the right comparison.
  2. Load the page with JavaScript off: with DevTools open, press Ctrl+Shift+P (Command+Shift+P), type "Disable JavaScript", select it and reload. Lists, reviews, maps or numbers that disappear are added by JavaScript. Switch back with "Enable JavaScript" when you are done.
  3. Check Google separately: in Search Console, use URL Inspection, click "Test live URL", then "View tested page" to see the HTML after Google has processed it. That is Google's view, not other AI tools'.
  4. Asking an AI is a last check, not proof: pasting a URL into an assistant is quick, but its own account is unreliable. In SearchEngineWorld's test, Perplexity told the user it could not access the page while the test server logged a successful fetch (HTTP 200) (SearchEngineWorld).

Check 3: see the real fetches in your server log

If you can read your server's access log, count which URLs AI crawlers actually requested. Most hosting control panels let you download the log.

# What did AI crawlers request? (combined log format, path in column 7)
# A request for a .js file or /wp-json/ after the page is NOT proof the script ran.
grep -E 'ChatGPT-User|OAI-SearchBot|Claude-User|Claude-SearchBot|Perplexity-User|PerplexityBot' access.log \
  | awk '{print $7}' | sort | uniq -c | sort -rn | head -30

A request for a .js file after the page does not prove the script ran. In Vercel's data, ChatGPT's and Claude's crawlers fetched JavaScript files but did not execute them (Vercel). A log tells you whether a crawler came and what you returned, nothing more.

Where WordPress sites hide facts behind JavaScript

WordPress builds post and page content into HTML on the server (in PHP), so ordinary body text is in the initial HTML. The risk is in what plugins, widgets and third-party embeds add later. Go through this table on your own site using the checks above.

On hidden text: in Writesonic's test, text hidden with CSS display:none was read by five of six assistants (Writesonic). Toggles are not the problem in themselves; what matters is whether the answer text is in the HTML.

The order to fix things

  1. Decide which facts you want AI to answer with: tax-inclusive prices, opening hours and closed days, service area, FAQ answers, basic company details. Five to ten per page.
  2. Use Check 1 or 2 to see whether each fact is in the initial HTML. If not, first write it into the body as text. That is the simplest fix and works for every AI tool.
  3. Make structured data and llms.txt come from the server. If you add them through a tag manager, move them to your theme or a plugin.
  4. Keep embeds and dynamic lists if you like, but add their key points to the body. Avoid serving bots different content: it lets what people see and what AI reads drift apart. Send everyone the same HTML.
  5. If the site is headless or built in the browser, ask your developer whether it can move to server-side rendering or pre-built HTML.
  6. After fixing, run Checks 1 to 3 again and log what you changed and when. Measure AI appearances again with the same questions (how to measure AI visibility).

FAQ

Do Google AI Overviews and AI Mode read content added by JavaScript?

Google says it processes JavaScript unless it is blocked. Do not expect the same from ChatGPT, Claude or Perplexity, so keep key facts in the initial HTML as well.

Will AI miss FAQ answers hidden in an accordion?

If the answer text is in the HTML and only hidden with CSS, it can be read. If it loads only after a click, it is not there. Search the page source for the answer text to be sure.

Is structured data added through Google Tag Manager wasted?

Google, which processes JavaScript, may read it, but crawlers that do not run JavaScript will not. Outputting it from the server through your theme or a plugin reaches both.

Is a WordPress site built with a page builder safe?

Most page builders generate HTML on the server, so ordinary text and headings are in the initial HTML. Some widgets and embeds load later, though, so check each component with Check 1 or 2.

If I publish llms.txt, can I ignore the JavaScript issue?

No. llms.txt helps as a guide to your site, but AI usually cites individual pages. The facts need to be in those pages' initial HTML first.

I pasted my URL into ChatGPT and the summary was right. Am I fine?

One success does not mean other pages or other days will behave the same. Assistants' own accounts have contradicted server logs, so the page source and access log are the reliable checks.

If my facts are in the initial HTML, will I appear in AI answers?

That cannot be guaranteed. It only meets the precondition for being read; AI answers change with the day, the wording and what other sites say. Measure again with the same questions after fixing.
