Building a New Client Site Ready for AI Search: From Discovery to Post-Launch Measurement

To build AI search readiness into a new site from the start: (1) in discovery, ask which questions the client hears most and where the master copy of each fact (prices, hours, service area) lives and who updates it; (2) plan one topic per page; (3) request copy in a question → one-to-two-sentence answer → details format; (4) decide that exactly one of the theme, the SEO plugin or a dedicated plugin outputs structured data; and (5) on launch day, check the staging privacy setting and how AI crawlers are treated. Each of these is cheaper to decide during planning and copywriting than to add after the build.

Written 20 November 2026 (JST). This guide is for agencies, freelance web designers and project leads who plan and build new client sites. If you are rebuilding an existing site and URLs or the domain will change, see Keeping AI search citations through a site redesign. For auditing a client's current site before a pitch, see First AEO audit and proposal; for post-launch work, see Offering AI search optimization monthly.

AI answers change from day to day and with the wording of the question. These steps help a site launch in a state where AI can read the client's facts correctly; they do not guarantee that it will appear in AI answers.

The whole build at a glance

Building for AI search does not add a new phase. It adds a few questions, decisions and checks to the phases you already run. Google says AI features such as AI Overviews have no additional requirements or special optimizations, and need no special structured data or new AI text files (AI features and your website, last updated 10 December 2025, checked 18 November 2026). The work is mostly ordinary site quality, applied to the accuracy and readability of facts.

The same Google page asks that structured data match the text visible on the page. That is why copy and structured data should come from the same source data.

Plan the sitemap and page types

Assign each collected question to the page that answers it. Keep one topic per page, and give fact-heavy content such as pricing, location and company details its own page rather than a section of the home page. When an AI looks up "what does this company charge", a page about only that makes the usable answer clear.

Make the copy request sheet question → answer → details

The most important thing in copy for AI search is a short answer to the page's question at the very top. But asking a client to "lead with the answer" usually returns a tagline or a welcome message. Build the question-and-answer shape into the fields of the request sheet itself.

[Copy request sheet] Page: Pricing (/pricing/)  Due: <date>  Approver: <name>
1. The questions this page answers (in the words customers actually use)
   e.g. How much is the first visit? When do extra charges apply?
2. The answer (1-2 sentences, with numbers, units, tax and an "as of" date)
   e.g. The first consultation is free; treatments start at $65 per session (as of November 2026).
3. Details (conditions, exceptions, what is not included)
4. What belongs in a table (plan / price / duration / conditions)
5. Where the master copy of this fact lives and who updates it
6. Anything that exists only in an image or PDF (send it as text)

A weak opening is "Pricing designed around you, for peace of mind": it contains no facts. A strong one is "The first consultation is free; treatments start at $65 per session (as of November 2026)": number, unit and date in one sentence. Keep a separate field for the design's tagline so the visual direction is not constrained.

Price lists, menus and timetables often arrive only as images or PDFs. Put a step in the first schedule to get them as text by the copy deadline, or to transcribe them and have the client confirm.

Build: decisions for the theme and templates

  1. Output facts as text. Do not put price lists or hours in images. Build tables with table markup.
  2. Do not hide key facts too deep in tabs or accordions. Google says it processes JavaScript unless it is blocked, and that perfectly semantic HTML is not required (Optimizing your website for generative AI features on Google Search, 10 July 2026). We have not checked official documentation on how other AI crawlers handle JavaScript, so when in doubt, keep the facts in the HTML itself.
  3. Write headings as questions or the words that match them ("Prices and when extra charges apply" rather than "Prices").
  4. Pick one source of structured data. If the theme, the SEO plugin and another plugin each output the business, a page can describe the same business twice. Decide who outputs what at the start of the build and record it.
  5. Use the same name, address, phone and hours in the copy and in structured data. Typing them into two places means one gets updated and the other does not, so output both from one setting where possible.
  6. Before launch, test the main pages with the Rich Results Test and the Schema Markup Validator.

Staging and launch day: the privacy setting and AI crawlers

WordPress's "Discourage search engines from indexing this site" (Settings > Reading) is often used on staging. Since WordPress 5.3, turning it on outputs `<meta name='robots' content='noindex,nofollow' />` on pages, and the `Disallow: /` line that robots.txt used to carry is no longer added (Make WordPress Core, 2 September 2019). In other words, the setting asks not to index; it does not block crawling. The same post recommends an X-Robots-Tag header, set in the server configuration, for non-HTML files such as images and PDFs.

While this setting is on (the WordPress option blog_public is 0), Nurevo AEO adds no AI search crawler groups to robots.txt and outputs no structured data. /llms.txt, however, depends only on the plugin's "Serve /llms.txt" setting, so it is served on staging too. Do not rely on this setting alone: protect staging with HTTP authentication or IP restrictions.

Copying the staging database to production carries the privacy setting with it. On launch day, work down this table:

# 1. Production robots.txt (are the AI search crawler groups there? no leftover Disallow: /?)
curl -s https://www.example.com/robots.txt

# 2. Is "Discourage search engines" off? (0 = still private, 1 = public)
wp option get blog_public
curl -s https://www.example.com/ | grep -i 'name=.robots'

# 3. llms.txt and Nurevo's output status
curl -s https://www.example.com/llms.txt | head -20
wp nurevo status

# 4. Move settings from staging (keys, tokens and the plan are not included)
wp nurevo export --file=nurevo-settings.json   # on staging
wp nurevo import nurevo-settings.json          # on production

Steps in WordPress (with Nurevo AEO)

These steps use the free Nurevo AEO plugin. With another plugin or by hand, the decisions are the same.

  1. Install it on staging and choose the site type in the setup wizard (local business, online shop, or B2B / SaaS). The type decides what is published for AI: business details, a product catalogue, or the organization and its services.
  2. Enter the name, address, phone, hours and description. The plugin fills only blank fields from sources such as SEO plugin settings and never overwrites typed values. Use the official name from discovery and the same values as the copy.
  3. Add each service with its page URL and booking URL.
  4. Place the "Nurevo FAQ" block on the FAQ page. FAQ structured data is output only on pages where the block or shortcode appears.
  5. Use per-page settings to leave thank-you pages, test pages and anything AI need not read out of llms.txt. llms.txt lists at most 30 pages, most recently modified first, so this matters most on sites with many posts.
  6. With Yoast SEO, Rank Math, All in One SEO or Slim SEO, missing facts are added inside their structured data, so the business is not described twice. SEO SIMPLE PACK and VK All in One Expansion Unit are also supported (since 0.9.1). If the theme outputs its own structured data, check with the Rich Results Test before launch.
  7. Training crawlers (GPTBot, ClaudeBot, Google-Extended and others) are left to the site's robots.txt by default. Allow or block them according to the policy agreed in discovery. This is separate from AI search crawlers; blocking them does not affect AI search or the score.
  8. On production, move the staging settings with Settings > Tools export (or wp nurevo export). Keys, tokens, the plan and the connection are not exported, so reconnect paid plans on production. Check that no staging URL is left in the organization URL setting.
  9. After launch, use wp nurevo status or the score in the dashboard to confirm structured data, llms.txt and AI crawler rules are switched on.

Measuring after launch when there is no "before"

A new site has no past numbers to compare with, so create a baseline on launch day. From the discovery questions, pick about ten that do not include the business name ("best [service] in [city]", "how much does [service] cost"), ask them in ChatGPT, Perplexity and Google's AI Overviews, and record whether the client is named, whether the site is cited, and whether the facts are right. AI answers change from day to day, so ask each question on at least two different days.

After that, compare the same questions at set points, such as one and three months later. For Google's AI features, Search Console's generative AI performance report has been available to all sites since 31 August 2026 (Search Console and AI features). Nurevo's free check at /check shows how readable the site is to AI. Ongoing AI visibility measurement is a Pro feature (beta), currently measured on Perplexity. New build checklist

  1. The questionnaire covers common questions, the master copy of facts and its owner, outside listings and the AI training crawler policy.
  2. A question-to-page map exists, with separate pages for pricing, location, about and FAQ.
  3. The copy request sheet uses question → answer → details, with numbers, units, tax and dates.
  4. Price lists and hours that existed only as images or PDFs are now text.
  5. Exactly one source outputs structured data, with the same values as the copy.
  6. Staging is protected by authentication.
  7. On launch day the privacy setting is off and the robots meta tag is checked.
  8. robots.txt and the WAF do not block AI search crawlers, and llms.txt lists production URLs.
  9. Search Console is set up and the sitemap submitted.
  10. Results for ten questions without the business name are recorded on launch day.

FAQ

For a new site, can't we just add AI search work after launch?

You can, but changing how copy opens or how pages are divided later means rewriting. Asking for common questions and the master copy of facts in discovery, and briefing copy as questions and answers, already cuts most of the rework.

Should we create llms.txt?

Google says Google Search does not use LLMS.txt. Whether other AI tools use it varies by company, so if it is cheap to produce, publish one with the same facts as the pages. A plugin can generate it automatically.

Is staging safe if "Discourage search engines" is on?

Since WordPress 5.3 the setting outputs a noindex meta tag; it does not block crawling in robots.txt. Protect staging with HTTP authentication or IP restrictions, and always confirm the setting is off on launch day.

What if the client cannot write the copy?

Ask the questions in a meeting, write the answers up yourself and have the client confirm them. The client must confirm the facts (numbers, dates, conditions); do not fill them in by guesswork.

Should the theme or the SEO plugin output structured data?

Either works, but pick one. If both output the business, a page can describe it twice. Decide who outputs what at the start of the build and record it.

How much should we add to the quote?

We do not give amounts because we found no reliable source for market rates. Build it up line by line from your own time records: discovery, page map, copy editing, setup, launch checks and the baseline.

If we follow these steps, will the site appear in AI answers right after launch?

That cannot be guaranteed. AI answers vary by day and wording, and how long it takes for a new site to be read is not published. These steps make sure that when the site is read, its facts come across correctly.
