新規サイト制作にAI検索対策を最初から入れる手順：ヒアリングから公開後の測定まで

新しいサイトにAI検索対策を最初から入れるには、①ヒアリングで「お客様がよく聞かれる質問」と「事実の正本（料金・営業時間・対応エリアなどの元データ）と更新する人」を聞き、②1ページ1つの話題でページの型を決め、③原稿を「質問→1〜2文の答え→くわしい説明」の形で依頼し、④構造化データを出すのはテーマ・SEOプラグイン・専用プラグインのどれか1つと決め、⑤公開日に、ステージングの非公開設定とAIのクローラーの扱いを確かめます。どれも、作り終えてから足すより、設計と原稿の段階で決めるほうが手戻りが少なくなります。

作成日：2026年11月20日（JST）。対象は、お客様の新しいサイトを企画・制作する制作会社・フリーランスのWebデザイナー・ディレクターです。いまのサイトを作り直してURLやドメインが変わる場合はリニューアルでAI検索の出典を失わない手順を、商談前にいまのサイトを診断する場合は初回診断と提案書の作り方を、公開後の月額の作業はAI検索対策を月額サービスにする方法を見てください。

AIの回答は日や聞き方によって変わります。この記事の手順は、AIがお客様の事実を正しく読める状態で公開するためのもので、AIの回答に出ることを保証するものではありません。

よく読まれている記事と、足りないこと

「ホームページ制作 AI検索対策」「Web制作 ヒアリングシート」「AEO checklist new website」などで上位に出る日本語4本と英語7本を、2026年11月20日に読みました（日本語のもう1社はサービスページを開いてもトップページの内容しか出ず、使えませんでした）。日本語では、AI検索に強いサイトの特徴を説明する記事（sungrove、2026年11月18日更新）と、制作会社のサービス紹介（jinrai、2026年11月18日更新）、ヒアリングシートの解説（発注ラウンジ 2026年9月8日、PRONIアイミツ 2025年1月8日更新）が上位でした。英語では、制作会社が自社の進め方を説明する記事（Aurum House、ColorWhistle、Xponent21、Orbit Media）と、AEOの解説（Avenue Z、Webflow、IMPACT）が中心でした。

結論を先に書く・見出しを整理する・構造化データを入れる・クロールを止めない、という点はほぼすべての記事で一致しています。一方で、制作の工程に落としたときに必要な次の点は、ほとんど書かれていませんでした。

記事ごとの良し悪しではなく、制作の工程で抜けやすい点をまとめています。上位の記事には「AIの引用が◯倍」といった数字もありましたが、出典がないか1社の自社データだったため、この記事では使っていません。

工程ごとに入れるもの：全体の表

AI検索対策を新規制作に入れるといっても、特別な工程が増えるわけではありません。いつもの工程の中で、聞くこと・決めること・確かめることが少し増えるだけです。Googleも、AIによる概要などのAI機能のために追加の要件や特別な最適化は必要なく、特別な構造化データや新しいAI向けのテキストファイルも要らないとしています（AI 機能とウェブサイト、2025年12月10日更新、2026年11月18日に確認）。だからこそ、通常のサイト作りの質を、事実の正しさと読みやすさの面で上げることが中心になります。

Googleは同じページで、構造化データはページに見えている文字と一致させるよう求めています。原稿と構造化データの値を同じ元データから作るのは、このためです。

ヒアリングシートに足す8項目

ヒアリングシートの解説記事が挙げる項目（会社の基本情報、目的、ターゲット、競合、デザイン、掲載したい内容、素材、予算と納期）は、そのまま使えます。そこに、AI検索のために次の8項目を足します。どれも、後から聞き直すと原稿の書き直しになる項目です。

「よく聞かれる質問」は、お客様に一覧を書いてもらうより、電話やメールの問い合わせを一緒に見返すほうが集まりやすくなります。
足す項目聞き方の例なぜ要るか
よく聞かれる質問（10〜20個）電話・メール・窓口・営業の場で、初めての人によく聞かれることは？　その時の言い方でAIに聞かれる質問に近い。ページの割り当てとFAQの元になる
正式な名前と表記のゆれ正式名称、略称、英字表記、旧社名・旧店名はありますかAIや外部の掲載先で別の名前が使われていると、同じ会社だと分かりにくい
事実の正本と更新する人料金・営業時間・対応エリア・定休日は、どこに元データがあり、変わったときに誰が知らせますか公開後に古い事実が残るのを防ぐ。保守の範囲を決める材料にもなる
外部の掲載先Googleビジネスプロフィール、予約サイト、ポータル、SNS、業界団体の名簿に載っていますか。管理者は誰ですかサイトと外部で住所・電話・時間が食い違わないようにそろえる
数字と実績の根拠「実績◯件」「創業◯年」の数字は、いつ時点で、何を数えたものですか原稿に時点と数え方を書ける。根拠のない数字を載せない
業種の広告ルール医療・士業・不動産など、表示に決まりのある業種ですか体験談や比較の書き方に制限がある業種では、原稿の段階で直すほうが早い
AIの学習用クローラーの方針AIの学習のための収集（GPTBot など）を許可しますか、止めますかAI検索への表示とは別の判断。お客様に決めてもらい、記録しておく
比べられる相手お客様が他にどこと比べて選んでいますか比較の質問（◯◯と△△の違い）に答えるページや表を作るかを決める

サイトマップとページの型を決める

集めた質問を、どのページで答えるかに割り当てます。1つのページには1つの話題を置き、料金・アクセス・会社概要のように事実がまとまっているページは、トップページの一部ではなく独立したページにします。AIが「この会社の料金は」と調べたときに、そのことだけを書いたページがあれば、答えに使える範囲がはっきりします。

質問とページの対応表は、ワイヤーフレームと一緒にお客様に見せると、「この質問の答えはどのページにあるか」を確認でき、原稿の抜けも見つけやすくなります。
ページ冒頭の1〜2文で答えること載せる事実主な構造化データくわしいガイド
トップ何の会社・お店で、どこで、誰のためにあるか名前、所在地または対応地域、主なサービスOrganization または LocalBusiness の詳しい型、WebSite―
サービス（1つずつ）このサービスは何で、誰に向いているか内容、対象、所要時間、料金の目安、申し込み方法Service（会社とつなぐ）―
料金いくらで、何が含まれ、税込か料金表、単位、時点、追加料金の条件Offer など（本文と同じ値）料金ページ
アクセス・営業時間どこにあり、いつ開いているか住所、地図、営業時間、定休日、駐車場LocalBusiness―
会社概要どんな会社か正式名称、設立、代表者、所在地、許認可Organization会社概要ページ
FAQ質問ごとに1〜2文でヒアリングで集めた質問FAQPage（ページに見えている質問だけ）FAQページ
代表・スタッフ誰が担当し、どんな資格・経歴か名前、役職、資格、経歴Person人物紹介ページ

原稿依頼シートを「質問→答え→くわしい説明」の形にする

AI検索のための原稿で一番大事なのは、各ページの最初に、質問への答えを短く書くことです。ただ、お客様に「結論を先に書いてください」と頼むだけでは、多くの場合キャッチコピーや挨拶文が返ってきます。依頼シートの欄そのものを、質問と答えの形にしておきます。

【原稿依頼シート】ページ：料金（/price/）　締切：◯月◯日　確認者：◯◯様
1. このページで答える質問（お客様がよく聞かれる言い方で）
   例）初回はいくらかかりますか？／追加料金がかかるのはどんなときですか？
2. 答え（1〜2文。数字・単位・税込/税抜・いつ時点かを入れる）
   例）初回カウンセリングは無料、施術は1回 8,800円（税込）からです（2026年11月時点）。
3. くわしい説明（条件・例外・対象外）
4. 表にしたい内容（コース名／料金／所要時間／条件）
5. この情報の正本と更新する人（例：料金表 Excel、店長が改定時に連絡）
6. 画像やPDFにしか載っていない情報はないか（ある場合は文字で）

悪い例は「お客様一人ひとりに寄り添った、安心の料金体系です」のように、事実が1つも入っていない書き出しです。良い例は「初回カウンセリングは無料、施術は1回 8,800円（税込）からです（2026年11月時点）」のように、数字・単位・税・時点が1文に入っているものです。デザインのキャッチコピーは別の欄に分けておけば、見た目の自由度は下がりません。

料金表・メニュー・時間割が画像やPDFでしか届かないことはよくあります。原稿の締切までに文字のデータをもらうか、制作会社が文字に起こしてお客様に確認してもらう段取りを、最初のスケジュールに入れておきます。

構築：テーマとテンプレートで決めること

  1. 本文の事実を文字で出す。料金表・営業時間を画像にしない。表は表のタグで作る。
  2. タブやアコーディオンに大事な事実を隠しすぎない。Googleは、ブロックされていなければJavaScriptも処理するとし、完全に意味づけされたHTMLは必須ではないとしています（Google 検索の生成 AI 機能のためのサイトの最適化、2026年7月10日）。ほかのAIのクローラーがJavaScriptをどう扱うかの公式の説明は、この記事では確認していません。迷ったら、HTMLにそのまま書かれている状態にしておくのが安全です。
  3. 見出しは質問か、質問に対応する言葉にする（「料金」より「料金と追加料金の条件」）。
  4. 構造化データの出し手を1つに決める。テーマ（SWELL・Lightning など）、SEOプラグイン、専用のプラグインがそれぞれ会社の情報を出すと、1ページに同じ会社が2つ載ることがある。どれが何を出すかを構築の最初に決めて記録する。
  5. 会社の名前・住所・電話・時間は、本文と構造化データで同じ値にする。手で2か所に入れると、どちらかだけ直されて食い違うので、なるべく1か所の設定から両方に出す。
  6. 公開前にリッチリザルト テストとSchema Markup Validatorで主なページを確かめる。

ステージングと公開日：非公開設定とAIのクローラー

WordPressの「表示設定」にある「検索エンジンがサイトをインデックスしないようにする」は、ステージングでよく使われます。WordPress 5.3以降、この設定をオンにするとページに `<meta name='robots' content='noindex,nofollow' />` が出力され、それまでrobots.txtに出していた `Disallow: /` は出さなくなりました（Make WordPress Core、2019年9月2日）。つまり、この設定はクロールを止めるものではなく、インデックスしないよう頼むものです。画像やPDFなどHTML以外のファイルには、サーバーの設定で X-Robots-Tag ヘッダーを付けるよう同じ記事で案内されています。

Nurevo AEOは、この設定がオンの間（WordPressのオプション blog_public が 0 の間）、robots.txtにAI検索のクローラーの行を足さず、構造化データも出しません。一方、/llms.txt はプラグインの「llms.txt を出す」の設定だけで決まるので、ステージングでも出ます。ステージングは、この設定だけに頼らず、Basic認証やIP制限で外から見えないようにしておきます。

ステージングのデータベースをそのまま本番に移すと、非公開の設定もそのまま本番に来ます。公開日には、次の表を上から確かめます。

# 1. 本番の robots.txt（AI検索のクローラーの行があるか、Disallow: / が残っていないか）
curl -s https://www.example.jp/robots.txt

# 2. 「検索エンジンがサイトをインデックスしないようにする」が外れているか
#    （0 なら非公開のまま。1 で公開）
wp option get blog_public
curl -s https://www.example.jp/ | grep -i 'name=.robots'

# 3. llms.txt と Nurevo の出力の状態
curl -s https://www.example.jp/llms.txt | head -20
wp nurevo status

# 4. ステージングから設定を移す（キー・トークン・プランは入らない）
wp nurevo export --file=nurevo-settings.json   # ステージングで
wp nurevo import nurevo-settings.json          # 本番で
確かめること起きやすいこと確かめ方
非公開設定が外れているかステージングの設定のまま公開し、noindex が全ページに出る表示設定のチェック、またはページのソースで robots の meta を見る
robots.txt にAI検索のクローラーの行があるか非公開の間は足されないため、外し忘れると行がない。サーバーに古い実ファイルの robots.txt が置かれているhttps://ドメイン/robots.txt で OAI-SearchBot・ChatGPT-User・Claude-SearchBot・Claude-User・PerplexityBot・Perplexity-User の扱いを見る
サーバー・CDN・WAFで止めていないか新しいサーバーのボット対策が初期設定でAIのクローラーを止める各社が公開しているUAとIPの範囲で許可する。Perplexityは設定の反映に最大24時間かかることがあるとしている（Perplexity：クローラー）
構造化データが1つで、本文と同じ値かテーマとプラグインの両方が会社の情報を出す。ステージングのURLが残るリッチリザルトテストと、ソースでステージングのドメインを検索
llms.txt に本番のURLが並ぶか会社のURLの設定にステージングのURLを手で入れたままhttps://ドメイン/llms.txt を開く
Search Consoleとアクセス解析本番のドメインで所有権の確認をしていないプロパティを作り、サイトマップを送る

WordPressでの手順（Nurevo AEOを使う場合）

ここでは、無料のプラグインNurevo AEOを使う場合の手順を書きます。別のプラグインや手作業でも、決めることは同じです。

  1. ステージングに入れ、初回の設定ウィザードで種類（店舗などの地域のお店・ネットショップ・BtoB／SaaS）を選ぶ。種類によって、AI向けに出す内容（店舗の情報か、商品の一覧か、会社とサービスか）が変わる。
  2. 名前・住所・電話・営業時間・説明を入れる。プラグインはSEOプラグインの設定などから空欄だけを埋め、入力した値は上書きしない。ヒアリングで決めた正式名称と、原稿と同じ値を入れる。
  3. サービスを1つずつ入れ、それぞれのページのURLと予約のURLを入れる。
  4. FAQページに「Nurevo FAQ」ブロックを置く。FAQの構造化データは、このブロックかショートコードを置いたページにだけ出る。
  5. お礼ページ・テスト用のページなど、AIに読ませる必要のないページは、ページごとの設定で llms.txt から外す。llms.txt に並ぶページは、最近更新された順に最大30件なので、記事の多いサイトでは特に効く。
  6. SEOプラグインを使う場合は、Yoast SEO・Rank Math・All in One SEO・Slim SEO の構造化データの中に足りない事実が足されるので、会社の情報が2つにならない。SEO SIMPLE PACK と VK All in One Expansion Unit とも併用できる（0.9.1から）。テーマが自前の構造化データを出す場合は、公開前にリッチリザルトテストで確かめる。
  7. 学習用クローラー（GPTBot・ClaudeBot・Google-Extended など）は、初期状態ではサイトの robots.txt に任せている。ヒアリングで決めた方針に合わせて、許可か拒否を選ぶ。AI検索のクローラーとは別の設定で、拒否してもAI検索への表示やスコアには影響しない。
  8. 本番では、設定 > ツールの書き出し（または wp nurevo export）でステージングの設定を移す。キー・トークン・プラン・接続は書き出されないので、有料プランの場合は本番でつなぎ直す。会社のURLの設定にステージングのURLが入っていないかも確かめる。
  9. 公開後に wp nurevo status か管理画面のスコアで、構造化データ・llms.txt・AIのクローラーの出力がオンになっているかを見る。

契約書や作業範囲の書類には、少なくとも次の4点を入れておくと、公開後の行き違いを防げます。①AIの回答は日や聞き方で変わり、表示や順位を保証しないこと。②学習用クローラーを許可するか止めるかはお客様が決め、その決定を記録すること。③料金・営業時間などの事実の正本はお客様が持ち、変わったときに知らせる人を決めること。④公開後の更新や測定は、保守契約がある場合に行うこと。

公開後の測り方：比べる前の数字がないサイトの場合

新しいサイトには、比べるための過去の数字がありません。そこで、公開日に基準を作ります。ヒアリングで集めた質問のうち、社名を入れない質問（「◯◯市 △△ おすすめ」「□□の料金はいくら」など）を10個ほど選び、ChatGPT・Perplexity・GoogleのAIによる概要で聞き、お客様の名前が出たか、サイトが出典に出たか、事実が正しいかを記録します。AIの回答は日によって変わるので、同じ質問を日を変えて2回以上聞いておきます。

その後は、1か月後・3か月後など決めた時期に同じ質問で比べます。GoogleのAI機能については、Search Consoleの生成AIのパフォーマンスレポートが2026年8月31日からすべてのサイトで使えます（Search ConsoleでAI機能の表示を見る方法）。Nurevoの無料のAIチェック（/check）では、AIからの読みやすさを確かめられます。AIでの登場率の継続的な計測は Pro プランの機能で、現在は Perplexity で測っています（ベータ版）。測り方のくわしい手順はAIでの登場率の測り方にまとめています。

新規制作のチェックリスト

  1. ヒアリングシートに、よく聞かれる質問・事実の正本と更新する人・外部の掲載先・学習用クローラーの方針を入れた。
  2. 質問とページの対応表を作り、料金・アクセス・会社概要・FAQを独立したページにした。
  3. 原稿依頼シートを「質問→答え→くわしい説明」の形にし、数字・単位・税・時点を入れてもらった。
  4. 画像やPDFにしかない料金表・時間を文字にした。
  5. 構造化データの出し手を1つに決め、本文と同じ値にした。
  6. ステージングを認証で守った。
  7. 公開日に非公開設定を外し、ページの robots の meta を確かめた。
  8. robots.txt・WAFでAI検索のクローラーを止めていないこと、llms.txt に本番のURLが並ぶことを確かめた。
  9. Search Consoleを設定し、サイトマップを送った。
  10. 公開日に、社名なしの質問10個の結果を記録した。

よくある質問

新規サイトなら、AI検索対策は公開後に足せばよいのでは？

足すことはできますが、原稿の書き出しやページの分け方は後から変えると書き直しになります。ヒアリングで質問と事実の正本を聞き、原稿を質問と答えの形で依頼するだけでも、手戻りは減ります。

llms.txt は作るべきですか？

Googleは、Google検索では LLMS.txt を使わないとしています。ほかのAIが使うかどうかは各社で違うため、作る手間が小さければ置いておき、本文と同じ事実を載せる、という扱いで十分です。プラグインで自動で作る方法もあります。

ステージングで「検索エンジンがサイトをインデックスしないようにする」をオンにしておけば安全ですか？

WordPress 5.3以降、この設定は noindex の meta を出すもので、robots.txt でクロールを止めるものではありません。ステージングはBasic認証やIP制限で守り、公開日にこの設定を外したかを必ず確かめてください。

お客様が原稿を書けない場合は？

ヒアリングの場で質問に口頭で答えてもらい、制作会社が答えの文にしてお客様に確認してもらう方法があります。事実（数字・時点・条件）はお客様に確かめてもらい、推測で書かないことが大切です。

構造化データはテーマとSEOプラグインのどちらで出すべきですか？

どちらでも構いませんが、1つに決めることが大切です。両方が会社の情報を出すと、1ページに同じ会社が2つ載ることがあります。構築の最初に、どれが何を出すかを決めて記録してください。

見積もりにはいくらくらい上乗せすればよいですか？

相場の確かな出典がないため、この記事では金額を書いていません。ヒアリング・対応表・原稿の整え・設定・公開日の確認・基準の記録の行ごとに、自社の作業時間から積み上げてください。

この手順で作れば、公開後すぐにAIに出ますか？

保証はできません。AIの回答は日や聞き方で変わり、新しいサイトが読まれるまでの期間も公開されていません。この手順は、読まれたときに事実が正しく伝わる状態で公開するためのものです。

公開前と公開日に、AIがサイトをどう読むか確認

無料のチェックは登録不要です。URLを入れると、構造化データ・llms.txt・AIのクローラーの扱いを確かめられます。ステージングの確認と公開日の確認に使えます。
