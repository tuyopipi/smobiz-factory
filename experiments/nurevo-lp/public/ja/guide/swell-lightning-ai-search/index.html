SWELL・LightningのAI検索対策：テーマの構造化データを活かして、重複させずに足りない事実を足す手順

SWELLとLightning（＋VK All in One Expansion Unit）は、サイトと記事を説明する構造化データ（WebSite・Article など）を自動で出します。一方、AIが店や会社を説明するのに使う住所・電話・営業時間・サービス、llms.txt、AI検索のクローラの許可は出しません（この記事で確認した範囲）。SEO SIMPLE PACK は構造化データを出しません。テーマの出力は残し、足りない事実だけを同じ事業者の情報として足し、最後に重複がないことをページごとに確かめるのが基本の手順です。

作成日：2026年11月11日（JST）。SWELLの出力内容は、SWELL 2.19.0 を2026年9月30日に検証した解説記事（出典を本文に記載）にもとづきます。今回はSWELL公式サイトを読み込めなかったため、テーマの版によって違う可能性があります。必ず後半の手順で、ご自分のサイトの実際の出力を確認してください。

どんな設定をしても、ChatGPT・Perplexity・GoogleのAIに必ず表示される、順位が保証されるということはありません。AIの回答は日々変わります。この記事の目的は、AIがあなたのサイトの事実を「読み違えない」状態にすることです。

構成ごとに、いま何が出ているか

国内のWordPressでよく見る組み合わせごとに、構造化データ（JSON-LD など）の出力をまとめました。左の列が自分のサイトの構成です。

SEO SIMPLE PACK・VK ExUnit の内容は、Nurevo AEO 0.9.1 の開発時に各プラグインのコードで確認したもの（版は表のとおり）。
構成出している構造化データAIに足りないもの
SWELL（2.19.0）トップ：WebSite・Organization。投稿・固定ページ：WebSite・WebPage・Article・Organization。カテゴリーなど：CollectionPage。パンくずがあれば BreadcrumbList。FAQブロックは出力設定がオンのとき FAQPage（解説記事）Organization は名前・URL・ロゴ・SNSのリンクが中心で、住所・電話・営業時間は含まれない。llms.txt・AIクローラの許可もなし
SEO SIMPLE PACK（3.7.0）なし。meta タグ・OGP・認証コードなどを出すプラグインで、JSON-LD は出さない構造化データ全般（テーマが出す分を除く）
Lightning ＋ VK ExUnit（9.123.1）ExUnit がトップに WebSite、記事に Article を出す。Lightning のパンくずはHTMLに埋め込む形式（microdata）の構造化データ（Lightning 変更履歴）事業者の情報（ExUnit は事業者のノードを出さない）、FAQ、llms.txt、AIクローラの許可

つまり、どの構成でも「ブログやサイトの説明」はある程度出ていて、「店や会社の事実」と「AI向けの入口（llms.txt・クローラの許可）」が抜けています。ここを埋めるのが、テーマを使ったサイトのAI検索対策の中心です。

テーマの構造化データだけでは足りない理由

「土曜も開いている近くの整骨院は？」「〇〇市でWordPressに強い制作会社は？」のような質問に答えるとき、AIが必要とするのは、業種・所在地・電話・営業時間・提供しているサービス・料金の目安といった事実です。テーマが出す Article や WebSite は「このページは誰がいつ書いた記事か」を説明するもので、これらの事実は入っていません。

もちろん、ページの本文に住所や営業時間が書いてあればAIはそれを読めます。ただ、フッターやバナー画像の中に散らばっていると読み違えやすく、構造化データ・llms.txt で同じ事実をはっきり渡しておくと、本文とあわせて確かめられる材料が増えます。大事なのは、本文・構造化データ・Googleビジネスプロフィールで事実が食い違わないことです。

まず重複を確かめる：5分でできる手順

  1. 確かめるページを3種類決めます：トップページ、ふつうの投稿1本、FAQブロックを置いた固定ページ（あれば）。
  2. それぞれをリッチリザルト テストまたはSchema Markup Validatorにかけ、検出された型（@type）を書き出します。
  3. 同じ型が2つ出ていないかを見ます。特に、事業者（Organization や LocalBusiness）が別々の @id で2つ、WebSite が2つ、Article と BlogPosting が別々に1つずつ、FAQPage が2つ、の4つに注意します。
  4. ブラウザでページのソースを開き「application/ld+json」で検索すると、出力の塊がいくつあるか、どれがテーマでどれがプラグインかを見分けやすくなります。
  5. 重複があれば、どちらか一方を残すと決め、もう一方を止めます（次の章）。止めたら、同じ3ページでもう一度テストします。

重複そのものがすぐに大きな問題になるとは限りませんが、同じ会社が2社あるように見える、記事が2本あるように見える状態は、AIにも検索エンジンにも余計な判断をさせます。一度確かめておけば、テーマやプラグインを更新するまで同じ状態が続きます。

SWELL ＋ SEO SIMPLE PACK での整え方

いちばん多い組み合わせです。SEO SIMPLE PACK は meta と OGP のために残し、SWELL の構造化データも残したまま、足りない事実を足します。Nurevo AEO を使う場合の動きは次のとおりです（0.9.1）。

  1. Nurevo AEO の設定で、業種（歯科・美容室など）、住所、電話、営業時間、メール、サービス、FAQを入力します。空欄は、SEOプラグインの設定やWordPressの設定から読める範囲で補われ、入力済みの値は上書きされません。
  2. SEO SIMPLE PACK が有効だと、Nurevo AEO はトップページを自分で読み込み（有効化時・保存時・プラグインの組み合わせが変わったとき・毎日）、他が出している型を記録します。SWELL の WebSite が見つかれば、自分の WebSite は出しません。
  3. SWELL の Organization に住所や電話がなければ、Nurevo AEO は同じ @id で事業者の情報を出し、1つの事業者として足し合わされるようにします（SWELL の Organization に @id がない場合は自分の @id を使います）。
  4. 注意：この読み込みはトップページだけです。SWELL はトップに Article を出さないため、投稿ページでは SWELL の Article と Nurevo AEO の BlogPosting が両方出ることがあります。前の章の手順で投稿ページを確かめ、2つ出ていたらどちらかに寄せます。
  5. 寄せ方の例：SWELL の Article を残す場合は、Nurevo AEO の開発者向けフィルター webmcp_canary_schema_graph で、core から BlogPosting と WebPage を外します。逆に Nurevo AEO に任せる場合は、SWELL設定 →「構造化データ」の「JSON-LDを自動生成する」をオフにできますが、SWELL の BreadcrumbList も止まる点に注意します（Nurevo AEO はパンくずを出しません）。
  6. FAQは1ページに1か所。SWELL のFAQブロックの構造化データは、共通のJSON-LDをオフにしても止まりません。同じページに Nurevo のFAQブロック（または [nurevo_faq]）を置くと FAQPage が2つになるので、どちらか一方にします。

SWELL の設定名と、FAQブロックが共通設定と別に動く点は、解説記事（JSON-LDを止める方法）の SWELL 2.19.0 での検証によるものです。SEOプラグインを何も入れずに SWELL だけで運用している場合、Nurevo AEO 0.9.1 は控える判断をせず自分の一式を出すため、WebSite などが重なりやすくなります。この場合も上の手順で確かめてください。

Lightning ＋ VK ExUnit での整え方

Lightning では、構造化データは主に ExUnit が担当します。ExUnit の構造化データは「Structured data - WebSite」「Structured data - Article」の2つの機能で、ExUnit の有効化設定でそれぞれオン・オフできます。Nurevo AEO 0.9.1 は ExUnit に合わせて、次のように動きます。

  1. ExUnit が WebSite や Article を出しているページでは、Nurevo AEO は自分の WebSite・記事のノードを出しません。
  2. ExUnit の Article には、足りない項目（事業者を指す publisher、説明文、言語）だけを ExUnit のフィルター（veu_article_structure_data）で足します。著者など ExUnit が設定した値は変えません。
  3. ExUnit は事業者のノードを出さないので、住所・電話・営業時間を持つ事業者の情報は Nurevo AEO の1つだけになります。
  4. ExUnit の構造化データをオフにしている場合は、Nurevo AEO が自分の WebSite・記事のノードを出します。
  5. Lightning のパンくずは microdata で、Nurevo AEO はパンくずを出さないため、ここは重なりません。

Lightning 本体は2026年9月9日の 15.42.0 まで更新が続いています（変更履歴）。パンくずの表示位置の変更は Lightning G3 Pro Unit の機能です（Lightning の特徴）。テーマや ExUnit を更新したあとは、重複の確認をもう一度行うと安心です。

llms.txt と AIクローラの許可は、テーマとは別に用意する

この記事で確認した資料の範囲では、SWELL・Lightning・SEO SIMPLE PACK・ExUnit の機能として llms.txt の出力や、AI検索のクローラを名前で許可する設定は挙がっていません。テーマを替えても変わらない部分なので、プラグインか手作業で用意します。

Nurevo AEO の内容は WordPress.org の readme（0.9.1）による。
項目役割Nurevo AEO（無料）での扱い
llms.txtサイトの概要と主なページの一覧を、AI向けにテキストでまとめたもの/llms.txt で配信。WordPressの内容からプラグイン内で作るため、サイトキーも通信も不要
AI検索のクローラChatGPT・Claude・Perplexity が回答のためにページを読みに来るボットrobots.txt で OAI-SearchBot・ChatGPT-User・Claude-SearchBot・Claude-User・PerplexityBot・Perplexity-User を許可。/wp-admin/ など既存のルールはそのまま
AIの学習用クローラAIモデルの学習のために集めるボットGPTBot・ClaudeBot・Google-Extended・Applebot-Extended・CCBot は既定で robots.txt に任せ、ワンクリックで許可・拒否を選べる。拒否してもAI検索やスコアには影響しない

Nurevo AEO の詳しい仕様はWordPress.org のプラグインページにあります。

robots.txt で許可していても、サーバーやCDNのボット対策の設定で止まっていることがあります。ホスティングの管理画面にボット対策の項目があれば、AI検索のクローラを止めていないかもあわせて確認します。

チェックリスト

  1. トップ・投稿・FAQのある固定ページの3つで、事業者・WebSite・記事・FAQPage がそれぞれ1つずつになっている
  2. 事業者の情報に、業種・住所・電話・営業時間が入っていて、本文・Googleビジネスプロフィールと同じ表記になっている
  3. FAQブロックは、SWELL か Nurevo のどちらか一方だけをページに置いている
  4. https://（自分のドメイン）/llms.txt が開き、主なページ（料金・サービス・会社情報・アクセス）が載っている
  5. robots.txt にAI検索のクローラの許可があり、学習用クローラの扱いを自分で決めている
  6. テーマ・SEO SIMPLE PACK・ExUnit を更新したら、3ページで重複の確認をやり直す

効果の確かめ方

設定直後は、まず無料チェックで、構造化データ・llms.txt・AIクローラの許可が読める状態かを確かめます。Nurevo AEO をサイトとつないでいる場合、無料版とStandardでも月に1回、業種と地域から作った3つの質問を Perplexity に聞き、回答があなたの事業者名を挙げたか・サイトを出典にしたかを記録します（質問に事業者名は入れません）。Pro（月14,800円〜、ベータ）では、競合との比較と推移を測れます（現在は Perplexity。ChatGPT は設定され次第）。

AIの回答は同じ質問でも日によって変わるため、1回の結果で判断せず、同じ質問を続けて記録して傾向を見ます。測り方の詳細はAIでの登場率の測り方にまとめています。

よくある質問

SWELLを使っていれば、AI検索対策の構造化データは十分ですか？

記事やサイトの説明（WebSite・Article・パンくずなど）は出ていますが、確認した範囲では住所・電話・営業時間を持つ事業者の情報、llms.txt、AIクローラの許可は含まれません。店舗や会社のサイトなら、これらを足すと AI が事実を確かめやすくなります。

SEO SIMPLE PACK は構造化データを出しますか？

出しません。meta タグ・OGP・認証コードなどを出すプラグインです（3.7.0 のコードで確認）。そのため SWELL と組み合わせた場合、構造化データは SWELL の出力が中心になります。

SWELLのJSON-LDはオフにしたほうがいいですか？

多くの場合は残して構いません。足りない事業者の情報だけを足し、投稿ページで Article が2つになっていないかを確かめれば十分です。オフにするとパンくずの構造化データも止まる点に注意してください。

Lightning で Nurevo AEO を入れると、ExUnit と構造化データが重なりませんか？

Nurevo AEO 0.9.1 は、ExUnit が WebSite・Article を出しているページでは自分の分を出さず、ExUnit の Article に足りない項目だけを足します。ExUnit は事業者のノードを出さないので、事業者の情報は1つになります。

llms.txt を置けば ChatGPT に出るようになりますか？

表示が保証されるものではありません。llms.txt はサイトの要点をAIが読みやすい形で渡す補助です。本文・構造化データ・Googleビジネスプロフィールの事実をそろえることとあわせて行います。

テーマを SWELL から Lightning に変えたら、やり直すことはありますか？

あります。テーマごとに出す構造化データが違うので、変更後にトップ・投稿・FAQのある固定ページの3つで重複の確認をやり直してください。llms.txt と robots.txt の設定はテーマに依存しないため、プラグインで出していればそのまま残ります。

まず、AIがあなたのサイトを読めるか確認

登録不要の無料チェックで、構造化データ・llms.txt・AI検索のクローラの許可の状態がわかります。SWELL・Lightning のサイトなら、Nurevo AEO で足りない事実を無料で足せます。
