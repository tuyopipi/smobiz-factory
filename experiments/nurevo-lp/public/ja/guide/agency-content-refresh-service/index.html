既存記事のAI検索向けの見直しを、制作会社の月額サービスにする方法

既存記事の見直しを月額にするなら、最初に全記事の棚卸しを1回のスポット作業として行い、月額の中身は「決めた本数の記事を、残す・更新・書き直し・統合・外すのどれかに判定して作業し、前後を同じ条件で比べて報告すること」にします。AIに引用されるかは約束できないため、契約では本数・作業の種類・報告を約束し、統合や削除は必ずお客様の承認を取ってから行います。

作成日：2026年11月18日（JST）。対象は、お客様のWordPressサイトを保守している制作会社・SEO会社・WordPress保守会社です。1本の記事をどう書くかはAIに引用される記事の書き方、AI検索対策の月額サービス全体の設計は月額サービスにする方法にまとめています。この記事は、その間にある「お客様のサイトにすでにある記事の山をどう扱い、どう売るか」に絞っています。

AIの回答は同じ質問でも日や回によって変わります。ここで書く作業は、AIが読む記事の事実を正しく新しく保つためのもので、引用や表示を保証するものではありません。

よく読まれている記事に書かれていないこと

「リライト AI検索」「content refresh AI search」で上位に出る日本語6本・英語7本を2026年11月18日に読みました。冒頭に答えを書く、見出しを質問の形にする、表や箇条書きにする、といった1本の書き直し方はどの記事も詳しく扱っています。一方で、制作会社が月額で回すときに必要な次の点は、ほとんど書かれていませんでした。

記事ごとの良し悪しではなく、月額サービスとして回すときに必要な情報が抜けやすいという傾向を挙げています。
抜けていた点上位記事の状況
統合・削除・転送の判定基準日本語ではサービス紹介ページ1本が「自社記事同士が同じ検索語で競合したら統合して転送」と書くだけ。英語ではAirOpsとThe Rank Mastersが判定の種類を挙げている
更新日の扱い日本語の記事では見当たらず。英語のWinston Digital・Digital Appliedが「中身を変えたときだけ更新日を変える」と書いている
WordPressで保存のたびに更新日が変わることどの記事にもない
前と後の比べ方日本語はSearch Consoleのクリック率の比較か、手で聞いた結果の記録が中心。英語ではAirOpsが30・60・90日で比べる手順を書いている
契約で成果を保証しない書き方、価格の決め方成果を約束しない旨の記載はThe Rank Mastersだけ。価格は自社サービスの宣伝か、出典のない相場
数字の出典「FAQの構造化データの引用シェア」など、出典が書かれていない数字が多い。英語の数字の多くは書き手の会社自身の調査

サービスの形：初回の棚卸しと、毎月の見直し

棚卸しを月額に含める場合は、最低契約期間を決めておくと費用を回収しやすくなります。
区分作業頻度お客様に渡すもの
棚卸し（スポット）公開中の全記事を一覧にし、判定と優先順位をつける契約時に1回棚卸しの表、最初の3か月の作業予定
毎月の見直し決めた本数の記事を判定どおりに作業する（更新・書き直し・統合・外す）毎月作業した記事の一覧と、変えた内容

Googleは、AIによる概要やAIモードに表示されるために特別な最適化は要らず、通常のSEOのベストプラクティスが当てはまると説明しています（Google 検索セントラル：AI機能とウェブサイト）。既存記事の見直しは、SEOの保守とほとんど同じ作業です。違いは、AIが記事の一部を抜き出して使うことを前提に、事実の新しさと、抜き出しても意味が通る書き方を重く見る点です。

生成AIパフォーマンスレポートは2026年8月31日から全世界のサイトで使え、ページごとの表示回数を見られます。クリック数は出ないため、通常の検索パフォーマンスと並べて読みます（Search Console ヘルプ、詳しくはSearch ConsoleでAIの表示を見る方法）。

判定の5つ：残す・更新・書き直し・統合・外す

統合と外すは、お客様のサイトからページが減る作業です。判定の段階で一覧を見せ、承認を記録してから作業します。
判定当てはまる記事やること
残す事実が新しく、答えている質問がはっきりしていて、読まれている触らない。触らないことも作業の記録に書く
更新答えは合っているが、料金・制度・数字・画面の説明が古い古い事実だけを直し、直した内容と時点を本文に書く
書き直し質問への答えが冒頭にない、どの質問に答えているかわからない答える質問を1つに決め直し、冒頭2〜3文で答える形に組み直す。URLは変えない
統合同じ質問に答える記事が2本以上あるいちばん読まれている（または内容の良い）1本に中身をまとめ、他の記事は恒久的な転送（301）でまとめた記事へ寄せる。サイト内リンクも付け替える
外す事業として扱わなくなった内容、終わったキャンペーン、誤りを直せない記事お客様の承認を取ってから、近い内容の記事へ転送するか、公開をやめる

迷ったときの順番は、「読まれている記事を壊さない」が先、「AIに使われやすくする」が後です。Search Consoleで表示やクリックが多い記事は、書き直しより更新から始めると、失敗したときに戻しやすくなります。WordPressのリビジョン（変更履歴）が残っているかも、作業前に確かめておきます。

転送の種類、削除したページの扱い（404・410）、正規URLの指定についてのGoogleの細かい説明は、この記事を書いた日に原文を読めなかったため、ここでは書いていません。作業の前にGoogle 検索セントラルの該当ページで確かめてください。

更新日の扱い：中身を変えたときだけ変わるようにする

Googleは、ページが公開された日、または大きく変更された日をいくつかの手がかりから推定し、検索結果に日付として出すことがあると説明しています。勧めているのは、「公開日」「最終更新日」のようにラベルをつけて日付をページに見える形で書き、ArticleやBlogPostingの構造化データの datePublished・dateModified と一致させることです。未来の日付は書かないこと、日付の表示は保証されないことも書かれています（Google 検索セントラル：検索結果の日付）。

ここで制作会社が気をつけたいのが、WordPressの更新日時です。WordPressは投稿を更新して保存するたびに更新日時を新しくします。テーマが「最終更新日」をこの日時から表示している場合、誤字を1文字直しただけで、記事は「今日更新された」ように見えます。Nurevo AEOが記事に出すBlogPostingの dateModified も、このWordPressの更新日時です（SEOプラグインが記事の構造化データを出している場合は、そちらがそのまま使われます）。

作業更新日本文に書くこと
誤字・表記ゆれの修正なるべく変えない（毎月の更新作業とまとめて保存する）書かなくてよい
事実の更新（料金・制度・数字）変わる「2026年11月：料金を改定後の金額に更新」のように、何を直したか
書き直し変わる直した点と、答えている質問
統合まとめた先の記事の更新日が変わるどの記事の内容をまとめたか
中身を変えない保存変えない—

日付だけを新しくする作業は、サービスに入れません。Googleの「有用で信頼性の高い、ユーザー第一のコンテンツの作成」は、コンテンツがどのように作られたかを説明することを勧めています（Google 検索セントラル）。見直しの内容を本文の短い一文で残すことは、その説明にもなります。

llms.txt に載る記事は、更新の順番で変わる

Nurevo AEOが作る /llms.txt には、公開中の投稿と固定ページのうち、更新日時が新しい順に30件が載ります（ページごとの設定で「llms.txtに載せない」にしたものは除きます）。llms.txtは記事や設定が変わると作り直されます。

つまり、見直しで古い記事を保存すると、その記事がllms.txtの一覧に入り、代わりに別の記事が押し出されることがあります。終わったキャンペーンの記事を誤字修正のために保存しただけで、llms.txtに戻ってくることもあります。見直しの月には、作業の後に /llms.txt を開き、載せたくない記事が入っていないかを確かめ、外したい記事はページごとの設定で外します。

なお、Nurevoのサービスに接続しているサイトでは、計測のために、更新日時が新しい順に30件の投稿・固定ページのタイトルとURLが送られます。どの記事がAIに読まれる一覧に入っているかは、記事の更新の順番と結びついている、と考えておくと作業の順番を決めやすくなります。llms.txtの書き方

毎月の作業の流れ

  1. 月初：棚卸しの表から、その月に作業する記事を決める（例：更新3本と統合1件）。統合・外すがある月は、対象の一覧をお客様に送って承認をもらう。
  2. 作業前：作業する記事について、決めた質問をAIに聞いた結果と、Search Consoleの数字を記録する（次の節）。
  3. 作業：判定どおりに作業する。事実の確認が必要な箇所（料金・制度・監修が必要な内容）はお客様に確認してから直す。
  4. 作業後：構造化データの日付と本文の日付が合っているか、/llms.txt の一覧、転送が効いているか、サイト内リンクが切れていないかを確かめる。
  5. 翌月以降：作業から日を置いて、同じ条件で測り直し、レポートに載せる。

契約と価格の決め方

契約では成果ではなく作業を約束します。The Rank Mastersのサービスページも、作業と報告は約束するが、取り戻すアクセスは保証しないと明記しています（The Rank Masters）。契約書や提案書には、次のような文を入れておくと、後の食い違いを防げます。

  1. 「毎月◯本の既存記事について、判定（残す・更新・書き直し・統合・外す）に沿った作業と、作業前後の記録を報告します。AIの回答への表示・引用、検索順位、アクセス数の増加は保証しません。」
  2. 「記事の統合・転送・公開の停止は、対象の一覧をお送りし、ご承認をいただいてから行います。」
  3. 「料金・制度・医療や法律に関わる内容など、事実の確認が必要な箇所は、貴社のご確認をいただいてから公開します。」
  4. 「作業に生成AIを使う場合は、その範囲をお知らせし、公開前に担当者が事実と表現を確認します。」

価格は、相場から逆算するより、1本あたりの作業時間を判定ごとに決めて積み上げるほうが説明しやすく、赤字になりにくい方法です。たとえば「更新は1本あたり◯時間、書き直しは◯時間、統合は1件◯時間」と決め、月の本数を掛け、報告の時間を足します。最初の3か月は実際の時間を記録して、見積もりと合っているかを確かめます。制作会社向けの相場は、信頼できる一次情報が見つからなかったため書いていません。

記事を大量に書き換えて数を増やすことは、サービスの目的にしません。サービスを始める前に、Googleのスパムに関するポリシーも原文で読んでおきます。本数を約束する契約でも、1本ごとに直す理由が棚卸しの表にある状態を保ちます。

WordPressでの手順（Nurevo AEOを使う場合）

  1. お客様のサイトにNurevo AEO（無料）を入れ、構造化データ・llms.txt・AIクローラの許可の状態を診断する。Yoast SEO・Rank Math・All in One SEO・Slim SEO・SEO SIMPLE PACK・VK All in One Expansion Unitと併用でき、記事の構造化データはそれらが出しているものがそのまま使われる。
  2. テーマが本文に「最終更新日」を出しているかを確かめる。出していない場合は、日付の表示をテーマの設定で入れるか、本文の冒頭か末尾に更新の一文を書く。診断でも、表示の更新日か dateModified を出すことが勧められる。
  3. 見直した記事は、ブロックエディタの「Nurevo AEO」パネルで、その記事専用の質問と答えを入れられる（Nurevo FAQブロックを「このページの質問」にして置くと、その記事だけにFAQPageとして出る）。答えは本文に書いてある内容と同じにする。
  4. 外した記事や終わった告知は、同じパネルで「llms.txtに載せない」にする。作業後に /llms.txt を開いて一覧を確かめる。
  5. 統合した記事は、転送を設定したうえで、元の記事を指していたサイト内リンクを、まとめた記事のURLに付け替える。
  6. 月次レポートに、作業した記事・判定・変えた内容・作業前後の記録を載せる。

制作会社がNurevoを使う場合

制作会社・SEO会社向けには、社名・ロゴ・ブランドカラーで送れる月次レポート（PDFにも印刷可）、複数のお客様のサイトを1つの画面で見られるダッシュボードがあります。紹介したお客様の月額の40%（Stripe手数料控除後）をお支払いする紹介報酬もあります（承認制）。有料プランはお客様ご自身が同意のうえで契約し、制作会社は見直しの作業と報告に対して料金をいただく形です。詳しくはパートナープログラムをご覧ください。

正直に書くと、記事ごとの書き直し案を自動で出す機能や、多くのAIを横断して追う計測は、Nurevoにはありません。そうした作業は、記事制作の専用ツールや計測を専門にするツールのほうが向いています。Nurevoは、構造化データ・llms.txt・AIクローラの設定を正しく保つ土台と、月次の報告に使う、という分け方が現実的です。

月額の見直しのチェックリスト

  1. 全記事の棚卸しの表に、答えている質問と、時点のある事実を書いた。
  2. 判定（残す・更新・書き直し・統合・外す）と、その理由を表に書いた。
  3. 統合・外すの一覧について、お客様の承認を記録した。
  4. 作業前の記録（Search Console・生成AIレポート・決めた質問の結果）を取った。
  5. 誤字だけの修正で更新日を動かしていない。
  6. 事実を直した記事には、何を・いつ直したかを本文に書いた。
  7. 本文の日付と構造化データの日付が一致している。
  8. 統合した記事の転送とサイト内リンクの付け替えを確かめた。
  9. /llms.txt に載せたくない記事が入っていない。
  10. 作業後、作業前と同じ条件で測り直してレポートに載せた。
  11. 契約書・提案書に、成果を保証しないことと、承認の手順を書いた。

よくある質問

既存記事を見直せば、AIに引用されるようになりますか？

保証はできません。AIの回答は同じ質問でも日や回によって変わります。見直しで約束できるのは、記事の事実を新しくし、答えを読み取りやすくする作業と、その前後の記録です。結果は、作業前と同じ条件で測った記録として報告します。

新しい記事を書くのと、既存記事を見直すのはどちらが先ですか？

お客様のサイトにすでに記事が多く、料金や制度などの古い事実が残っているなら、見直しから始めるのがおすすめです。古い事実は、AIがその事業について間違った答えをする原因になります。同じ質問に答える記事がない場合は、新しい記事が必要です。

更新日を新しくするだけでも効果はありますか？

中身を変えずに日付だけを新しくする作業は、サービスに入れないことをおすすめします。Googleは、公開日または大きな変更があった日を推定して日付を出すと説明しており、本文の日付と構造化データの日付を一致させることを勧めています。

誤字を直しただけで最終更新日が変わってしまいます。

WordPressは保存のたびに更新日時を新しくします。誤字や表記の修正は、事実の更新と同じ月にまとめて保存すると、更新日が意味のない日付で動くのを減らせます。表示する日付をどこから取っているかは、テーマの設定で確かめてください。

記事を統合すると、検索からのアクセスは減りませんか？

減る可能性はあります。読まれている記事を残す側にし、他の記事は転送でまとめた記事へ寄せ、サイト内リンクを付け替えます。統合の前後で表示回数とクリック数をページ別に記録し、必ずお客様の承認を取ってから行ってください。

毎月何本くらい見直せばよいですか？

決まった数はありません。記事の総数、古い事実の多さ、お客様の確認にかかる時間で決めます。最初の棚卸しで優先順位をつけ、無理なく続けられる本数から始め、3か月ほど作業時間を記録して見直すのが現実的です。

生成AIで書き直してもよいですか？

下書きに使うことはできますが、公開前に担当者が事実と表現を確かめてください。Googleは、コンテンツがどのように作られたか、自動化やAIを使った場合はその使い方を説明することを勧めています。お客様にも、使う範囲を契約の段階で伝えておきます。
