代表者・専門家・著者のプロフィールページのAI検索対策：経歴・資格・専門分野をAIに正しく読ませる手順

人についての質問にAIが正しく答えられるかは、その人のプロフィールページが「誰が、どこで、何の専門家か」を文字で書いているかで決まります。氏名・役職・所属・資格・専門分野・経歴を1ページにまとめ、記事の著者名や会社概要の代表者欄からそのページへリンクし、同じ値をPersonの構造化データで出す。この3つが中心です。資格や実績を盛ること、架空の著者を作ることは、Googleがはっきり「欺瞞」と呼んでいるので逆効果です。

作成日：2026年11月16日（JST）。Googleの「有用で信頼性の高い、ユーザー第一のコンテンツの作成」（最終更新 2026年10月5日）と「プロフィール ページ（ProfilePage）の構造化データ」は同日に確認しました。対象は、代表者・院長・所長・講師・記事の書き手のページを持つ会社・店舗・事務所と、そのサイトを作る制作会社です。会社そのものの情報は会社概要ページのAI検索対策で扱っています。

AIの回答は日や聞き方によって変わります。この記事の手順は、AIが読む元の情報を正確にするためのもので、AIの回答に出ることや、検索順位が上がることを保証するものではありません。

AIは人物の情報を何に使うのか

ChatGPTの検索、Perplexity、GoogleのAIによる概要は、質問に答えるときにウェブのページを読み、出典として示します。人についての質問では、本人が所属する組織のサイトにあるプロフィールページが、いちばん直接の材料になります。そのページがない、写真と名前だけ、ページごとに肩書きが違う、という状態だと、AIは古い記事や同姓同名の別人の情報で答えを組み立てることがあります。

人についての質問には、次のような型があります。

  1. 「〇〇株式会社の代表は誰？どんな経歴？」（会社の代表者）
  2. 「〇〇クリニックの院長は何の専門医？」（専門家の資格と専門分野）
  3. 「梅田で相続に強い税理士は？」（専門分野からの発見。名前は入っていない）
  4. 「この記事を書いたのは誰？信頼できる？」（記事の著者）
  5. 「〇〇さんと△△社の関係は？」（所属・兼職・前職）
  6. 「〇〇先生に相談するには？」（連絡先・予約の窓口）

3つ目のように名前が入っていない質問では、AIはまず事務所や店を探し、そのうえで「誰が担当するか」を答えに足します。プロフィールページは、名前で聞かれたときだけでなく、専門分野で探されたときにも使われる材料です。

Googleが公式に言っていること（確認できた範囲）

著者情報やE-E-A-Tについては推測の多い記事がよく出回っています。まずGoogleが自分で書いていることを押さえます。

Googleの説明出典この記事での受け止め方
読者が著者を知りたいと思うところに、署名（バイライン）など正確な著者情報を付けることを強く勧める有用なコンテンツの作成記事に著者名を出し、名前からプロフィールに進めるようにする
AIで作った顔写真、作った名前、偽の資格などで作り手のプロフィールをでっち上げることは欺瞞で、低品質のしるし同上架空の著者・水増しした資格は書かない
E-E-A-Tそのものは特定のランキング要因ではない。要素のうち最も大切なのは信頼（Trust）。健康・お金・安全などの話題（YMYL）ではE-E-A-Tの重みが大きい同上E-E-A-Tは「点数」ではなく、信頼できる事実を出すための考え方として使う
ProfilePageは、1人の人物か1つの組織がページの主役で、そのサイトと結び付いているページ向け（著者ページ、ブログの自己紹介、会社の社員紹介など）。店のトップページは対象外ProfilePageの構造化データ代表者・専門家・著者のページに使い、会社のトップページには使わない
ProfilePageで必須なのは mainEntity（Person か Organization）とその name。dateModified は人が編集した日だけを反映する同上最小構成から始め、更新日は実際に直した日にする
AIによる概要やAIモードに出るための追加の要件や特別なマークアップはないAI 機能とウェブサイト構造化データは本文の答え合わせ。本文に書くことが先

ProfilePageの構造化データについて、Googleが説明している表示先は「ディスカッションとフォーラム」などの機能です。AIの回答への効果は書かれていません。この記事では、構造化データは「本文と同じ事実を機械にも読める形で出すもの」として扱います。

上位の記事でよく見る主張と、根拠の確かさ

「著者 E-E-A-T AI検索」で上位に出る日本語・英語の記事を10本読みました。手順やチェックリストが役に立つ記事も多い一方で、次のような主張は一次情報で確かめられませんでした。読むときの目安にしてください。

よく見る主張確かめた結果
「著者の資格がAIの引用判断の16％を占める」などの割合どの記事も元の調査へのリンクがなく、「割合」が何を測ったものかの定義もない
「Personの構造化データは必須」Googleの説明では必須なのはProfilePageのリッチな表示に出す場合の項目だけ。AIの回答に必須という説明はない
「sameAsは多いほどよい」根拠なし。本人が管理している、本人だとわかるプロフィールだけにするほうが安全
「監修者を付ければE-E-A-Tが上がる」名前だけの監修は効果の根拠がない。Googleは作り手を偽ることを欺瞞としている。監修した範囲と日付を書くことが先
「プロフィール文は〇〇字が最適」記事ごとに数字が違い、根拠もない。必要な事実が入っていれば長さは問わない

誰のページを、どこに置くか

サイトに出てくる人を、役割で4つに分けます。全員に長いページは要りません。AIに聞かれそうな人から順に作ります。

役割置き場所最低限書くことつなぎ方
代表者会社概要の中か、/about/代表者名/ のような専用ページ氏名・役職・経歴・会社での役割会社概要の代表者欄からリンク。構造化データでは会社の founder や employee から同じ @id を指す
専門家（院長・所長・講師など）スタッフ紹介の一覧と、1人1ページ資格・登録番号・専門分野・担当する診療やサービスサービスのページの「担当」からリンク
記事の著者WordPressの著者アーカイブか、固定ページ氏名・所属・書いている分野・記事の一覧記事の署名からリンク
外部の監修者監修者のページ（所属先のサイトへのリンク付き）氏名・資格・所属・監修した範囲記事に「監修：氏名（資格）、〇年〇月〇日」と書き、ページへリンク

同じ人を「代表」「著者」「監修」の3か所で紹介するときは、ページを分けず1ページにまとめ、氏名・肩書きの書き方をそろえます。AIは表記が違うと別の人だと受け取ることがあります。

プロフィールページに書く項目と、構造化データとの対応

次の表は、プロフィールページに書く項目と、AIの答えで起きやすい間違い、対応する schema.org のプロパティです。プロパティは schema.org の Person と ProfilePage の定義から選んでいます（型は schema-dts 2.1.0 で確認）。

項目書き方AIで起きやすい間違い構造化データ
氏名サイト全体で1つの書き方。読み・英字表記も1回書く同姓同名の別人と混ざるname、alternateName
役職・所属「株式会社〇〇 代表取締役」のように会社名とセットで前職や兼職先の肩書きで紹介されるjobTitle、worksFor
資格正式名称、登録番号（公開してよい場合）、登録団体、取得年資格の種類を取り違える（認定と専門医など）hasCredential（EducationalOccupationalCredential）
専門分野具体的に3〜5個。「何でもできます」と書かない専門外の分野で推されるknowsAbout
経歴年と出来事を1行ずつ。学歴・前職・独立の年時期の取り違え本文（出身校は alumniOf）
実績数字には時点と数え方を付ける（例：2026年10月時点、相談件数〇件）古い数字や大きすぎる数字が引用される本文だけ
受賞・掲載名称・年・主催者。リンクできるものはリンク受賞と単なる掲載が混ざるaward（受賞だけ）
外部のプロフィール本人が管理しているアカウントだけなりすましや同名のアカウントと結び付くsameAs
写真本人の写真。AIで作った顔写真は使わない—image
書いた記事・担当サービス一覧かリンクどの分野の人かわからない本文
最終更新日ページの最後に。肩書きが変わったらすぐ直す前の役職で紹介されるdateModified（ProfilePage）

knowsAbout について、schema.org は「専門性を示唆するが、それを意味するものではない」と説明しています（schema.org: knowsAbout）。専門分野を構造化データに入れるだけでは裏付けにならないので、本文に担当した事例や書いた記事を並べます。

文章の書き方：1文目で「誰か」を言い切る

  1. 1文目に氏名・役職・所属・専門を入れる。例：「山田花子は、株式会社サンプル（大阪市北区）の代表取締役で、中小企業の会計と相続税を専門にする税理士です。」
  2. 2文目に、ほかの人と区別できる事実（資格の登録年、所属団体、担当している地域）を書く。
  3. 資格は略さず正式名称で。医師なら厚生労働省の医師等資格確認検索のように、公的に確かめられる資格は、読者が確かめられることを書き添えてもよい。
  4. 経歴は表か年表にし、画像やPDFにしない。
  5. 「業界No.1」「誰よりも詳しい」のような比べようのない言い方は避け、事実（年数・件数・担当分野）に置き換える。
  6. 医療・士業など広告の規制がある業種は、肩書きや資格の書き方に業界のルールがあります。医療は病院・クリニックのAI検索対策も合わせて確認してください。

記事の著者表記と監修の書き方

記事には、本文の最初か最後に著者名を出し、その名前からプロフィールページにリンクします。「編集部」だけの署名でも構いませんが、その場合は編集部のページに、誰がどんな体制で書いているかを書いておきます。

外部の専門家に内容を確認してもらった場合は、著者とは分けて「監修」と書き、監修した範囲（例：「税金の計算部分」）と日付を添えます。schema.orgには、ページの内容を正確さの点で確認した人を表す reviewedBy があり、著者を表す author とは別のプロパティです。著者と監修者を同じ author に並べないようにします。

AIで下書きを作った記事は、Googleがコンテンツの作り方（自動化やAIを使ったか）を読者に示すことを勧めているので、必要に応じてその旨と、人が確認したことを書きます。

構造化データの例：ProfilePage と Person

最小構成の例です。値はすべて本文に書いてあることだけにします。会社のノードと同じ @id を worksFor で指すと、人と会社が1つの組み合わせとして読まれます。

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "ProfilePage",
  "dateModified": "2026-11-16",
  "mainEntity": {
    "@type": "Person",
    "@id": "https://example.jp/about/yamada/#person",
    "name": "山田 花子",
    "alternateName": "Hanako Yamada",
    "jobTitle": "代表取締役・税理士",
    "worksFor": { "@id": "https://example.jp/#organization" },
    "description": "大阪の中小企業の会計と相続税を専門にする税理士。",
    "knowsAbout": ["相続税", "中小企業の会計"],
    "hasCredential": {
      "@type": "EducationalOccupationalCredential",
      "name": "税理士",
      "credentialCategory": "国家資格"
    },
    "image": "https://example.jp/images/yamada.jpg",
    "sameAs": ["https://www.linkedin.com/in/example"]
  }
}
</script>

資格の型 EducationalOccupationalCredential には、資格の種類（credentialCategory）や認定した団体（recognizedBy）も書けます。sameAs には、本人が管理していて、本人だとはっきりわかるプロフィールだけを入れます。

WordPressでの手順（Nurevo AEOの場合）

Nurevo AEO（無料）を使っている場合、人物の情報は次のように扱われます。

  1. まず「ユーザー」→「プロフィール」で、記事を書く人の「ブログ上の表示名」を本名（またはサイトで使う名前）に直す。Nurevoが自分の構造化データを出している場合、投稿は BlogPosting になり、著者はこの表示名の Person として出ます。固定ページには著者を付けません。
  2. Yoast SEO・Rank Math・All in One SEO・Slim SEO を使っている場合、記事（Article）とその著者は、そのプラグインが出すとおりのままで、Nurevoは変えません。著者の設定はそのプラグインのユーザー設定で行います。VK All in One Expansion Unit の記事の著者も変更しません。
  3. 代表者を会社の構造化データに足したい場合と、プロフィールの固定ページに ProfilePage を足したい場合は、下の開発者向けフィルターを使います（Nurevoの入力欄にはありません）。SEOプラグイン併用時は、会社のノードの値はそのプラグインの値が優先されます。
  4. SEOプラグインがすでに著者のページに ProfilePage などを出していないか、ページのソースで確かめ、二重にならないようにする。
  5. /llms.txt を開き、プロフィールページが載っているか確かめる。llms.txtには更新日の新しい固定ページ・投稿30件が載るので、載っていなければ webmcp_canary_llms_txt_lines フィルターで行を足せます。
// 1) 会社のノードに代表者を足す（会社概要に書いている人だけ）
add_filter('webmcp_canary_business_node', function ($org, $settings) {
    $org['founder'] = array(
        '@type' => 'Person',
        '@id'   => home_url('/about/yamada/#person'),
        'name'  => '山田 花子',
    );
    return $org;
}, 10, 2);

// 2) プロフィールの固定ページ（スラッグ yamada）だけに ProfilePage を足す
add_filter('webmcp_canary_schema_graph', function (array $bundle) {
    if (!is_page('yamada')) {
        return $bundle;
    }
    $bundle['extra'][] = array(
        '@type'      => 'ProfilePage',
        'url'        => get_permalink(),
        'mainEntity' => array(
            '@type'     => 'Person',
            '@id'       => home_url('/about/yamada/#person'),
            'name'      => '山田 花子',
            'jobTitle'  => '代表取締役・税理士',
            'worksFor'  => array('@id' => $bundle['org_id']),
            'knowsAbout'=> array('相続税', '中小企業の会計'),
        ),
    );
    return $bundle;
});

WordPress以外のサイトでも、確かめる項目は同じです。登録不要の無料チェックにURLを入れると、構造化データ・llms.txt・AIクローラの許可の状態を確認できます。

確かめ方：名前を入れた質問で記録する

人物ページの対策は、名前を入れた質問で確かめます。同じ質問を同じAIに、日を変えて何回か聞き、記録します。1回の答えで判断しないでください。

記録すること例
日付・AI・質問11/16、Perplexity、「株式会社サンプルの代表の山田花子さんはどんな経歴？」
答えの中の事実役職・資格・専門分野・経歴が正しいか、1つずつ○×
出典自社のプロフィールページが出典に入ったか、別の人のページが使われたか
取り違え同姓同名の別人や、前職の肩書きが混ざっていないか

Nurevoの無料のAIチェック（サイトを接続したFree・Standardのサイトで月1回）は、業種と地域から作った質問で、名前を入れずに聞きます。人の名前を入れた質問は上の表で手で確かめます。Proの登場率の計測（ベータ版）は現在Perplexityが対象です。測り方の全体はAIでの登場率の測り方にまとめています。

プロフィールページのチェックリスト

  1. 1文目に氏名・役職・所属・専門が入っている。
  2. 氏名と肩書きの書き方が、会社概要・記事の署名・スタッフ紹介で同じ。
  3. 資格は正式名称で、取得年や登録団体がある。
  4. 専門分野が具体的で、担当した事例や書いた記事が並んでいる。
  5. 実績の数字に時点と数え方がある。
  6. 架空の人物、AIで作った顔写真、盛った資格がない。
  7. 記事の署名からプロフィールにリンクしている。監修は著者と分けて、範囲と日付がある。
  8. ProfilePage と Person の構造化データが本文と一致し、二重に出ていない。
  9. sameAs は本人が管理しているアカウントだけ。
  10. 肩書きが変わったらすぐ直し、最終更新日を更新している。
  11. 名前を入れた質問で、日を変えて確かめ、記録した。

よくある質問

小さな会社でも代表者のページは必要ですか？

会社概要の代表者欄に、氏名・役職・経歴が数行あれば十分なことが多いです。代表者が記事を書いている、講演や取材が多い、代表者の名前で検索される、といった場合は、専用のページに分けると事実が1か所にまとまります。

資格を持っていない人が書いた記事は、AIに使われにくいですか？

資格がないこと自体が問題になるという説明は、Googleにはありません。Googleが重視するとしているのは信頼で、実際の経験（何年、どんな仕事をしてきたか）を事実として書くことが材料になります。医療やお金の話題では、専門家の確認を受けたうえで監修として明記する方法もあります。

ペンネームで記事を書いてもいいですか？

構いません。ただし、架空の経歴や資格を付けないこと、ペンネームの人のページに、どんな立場で書いているかを事実として書くことが前提です。Googleは作り手のプロフィールをでっち上げることを欺瞞としています。

著者ページとProfilePageの構造化データは、どちらが先ですか？

本文のページが先です。構造化データは本文と同じ事実を機械にも読める形にするもので、本文にない事実を構造化データだけに書くことは避けてください。

監修者は author に入れるべきですか？

著者と監修者は分けます。schema.orgには、内容を正確さの点で確認した人を表す reviewedBy があります。ページの本文でも「執筆」と「監修」を分けて書きます。

代表者が交代しました。何を直せばいいですか？

会社概要、代表者のページ、構造化データの founder や employee、記事の署名、社外のプロフィール（SNS・業界団体の名簿など）を直します。前の代表者のページは、役職と在任期間を書いて残すか、新しいページに案内します。AIの答えに反映される時期は決まっていません。

この手順で、人物の情報がAIに必ず正しく出ますか？

保証はできません。AIの回答は日や聞き方で変わります。この手順は、AIが読む元の情報を正確にそろえ、取り違えを起きにくくするためのものです。

サイトの人物と会社の情報が、AIにどう読まれているか確認

無料チェックは登録不要で、URLを入れるだけで構造化データ・llms.txt・AIクローラの許可の状態がわかります。WordPressなら、無料のプラグインで会社の基本情報と記事の著者を構造化データに出せます。
