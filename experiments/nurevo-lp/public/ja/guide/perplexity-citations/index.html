Perplexityに自社サイトが引用される仕組みと、引用されているかの確かめ方

Perplexityは、質問を受けるとウェブを検索し、読んだページを回答の出典として番号付きで示します。サイト側でできることは、①Perplexityの2つのクローラー（検索用のPerplexityBotと、質問に応じてページを読むPerplexity-User）を robots.txt とWAF（ファイアウォール）で止めていないかを確かめ、②質問への答えと事実を本文の文字で書き、③社名を入れない質問で実際に引用されているかを繰り返し記録することです。どのページを出典に選ぶかの基準は、Perplexityから公開されていません。

作成日：2026年11月18日（JST）。ChatGPTを中心にした手順はChatGPTに載る方法、AIでの登場率の測り方全般はAIでの登場率の測り方で扱っています。この記事は、Perplexityに絞って、公式の資料で確かめられることと、サイト側で確かめる手順を書きます。

AIの回答は日や聞き方によって変わります。この記事の手順は、Perplexityがサイトを読める状態にし、引用されているかを正しく測るためのもので、回答に出ることや順位を保証するものではありません。

Perplexityについて、公式に分かっていること・分かっていないこと

Perplexityの回答には、多くの場合、本文の中の番号と、出典のリンクの一覧が付きます。どのページがどこで使われたかが見えるため、他のAIより「引用されたか」を確かめやすいのが特徴です。一方で、候補のページをどう集め、どう順位を付け、何件を出典にするかは公開されていません。

上位の記事には「候補を5〜10件集めて3〜4件を引用する」「候補は20〜50件」など具体的な数字がありますが、記事によって食い違い、Perplexityの資料に根拠を確認できませんでした。この記事では、Perplexityが自社の資料に書いていることだけを事実として扱います。

2つのクローラー：PerplexityBot と Perplexity-User の違い

Perplexityの資料に書かれている2つのクローラーは、役割も robots.txt との関係も違います。片方だけ許可していると、引用の確かめ方を誤ります。

PerplexityBotPerplexity-User
目的Perplexityの検索結果にサイトを出し、リンクするためにページを集めるユーザーが質問したときに、正確に答えるためにページを読み、回答にリンクを付ける
来るタイミング質問とは関係なく、定期的に誰かが質問したとき

通したいときrobots.txt で止めない＋WAFで公開IP範囲を許可WAFで公開IP範囲を許可
AIモデルの学習使わない、と説明使わない、と説明

ユーザーエージェントの書き方とIP範囲は、クローラーの説明とPerplexityBotのガイドに載っています。2つのページで例の書き方とIP範囲のファイルのドメインが少し違うため、WAFに登録するときは最新のページで確かめてください。

robots.txt とWAFの設定：通したい場合・止めたい場合

Perplexityの回答に自社サイトを出典として出したい場合は、2つのクローラーを止めないことが前提です。robots.txt で個別のグループを作る場合は、サイト全体に効かせている決まり（例：/wp-admin/ を読ませない）も、そのグループの中に書き直します。クローラーは自分の名前のグループがあると、そのグループの決まりだけを見るためです。

# Perplexity の検索・回答に使われるクローラーを通す例
User-agent: PerplexityBot
Allow: /
Disallow: /wp-admin/

User-agent: Perplexity-User
Allow: /
Disallow: /wp-admin/

robots.txt を直しても、サーバーやCDNのボット対策（WAF、レンタルサーバーの「海外からのアクセス制限」、セキュリティ用のプラグインなど）が先にアクセスを拒否していることがあります。Perplexityの資料は、WAFではユーザーエージェントとIP範囲の両方で見分けるよう説明しています。名前だけで許可すると、名前をまねた別のアクセスまで通ってしまうためです。

反対に、Perplexityに読まれたくない場合は、PerplexityBot を robots.txt で Disallow にし、Perplexity-User はWAFで止めます。止めても、他のサイトに書かれた自社の情報をもとに回答が作られることはあります。どちらの場合も、設定の反映には最大24時間かかることがあるとされています。

2025年のCloudflareの報告：知っておくべきこと

Cloudflareは2025年8月4日、Perplexityが、クロールを禁止したテスト用のドメインに対して、名乗らないクローラーでアクセスしていたと報告し、Perplexityを「確認済みのボット」の一覧から外したと公表しました（Cloudflareのブログ）。Perplexityはこの報告に反論しています（PC Gamer、2025年8月5日）。

サイト運営者にとっての意味は2つです。1つ目は、CloudflareなどのCDNを使っている場合、AIボットを止める設定がPerplexityにも効いている可能性があることです。引用されたいのに止めていないか、管理画面のボット対策の設定を確かめてください。2つ目は、読まれたくない場合に robots.txt だけに頼らず、WAFで止める設定もあわせて検討することです。どちらの主張が正しいかを、この記事では判断していません。

出典に選ばれやすくするために、ページ側でできること

Perplexityは選び方の基準を公開していませんが、出典として使える情報がページにないと、引用はされません。次は、Perplexityに限らず、AIが答えの根拠として使いやすいページにするための手入れです。記事の書き方の詳細はAIに引用される記事の書き方にまとめています。

  1. 質問に対する答えを、見出しのすぐ下の1〜2文で書く（「◯◯市で土曜に診療している歯科は？」なら、診療日と時間をそのまま書く）。
  2. 料金・営業時間・対応地域・対象など、答えになる事実を画像やPDFだけにせず、HTMLの文字や表で書く。
  3. 数字には、いつの時点の値か（「2026年11月改定」）と、他社の数字なら出典のリンクを付ける。
  4. 1ページで扱う質問を絞る。サービスや店舗ごとにページを分け、ページ同士で事実を食い違わせない。
  5. 社名・所在地・連絡先を、会社概要や構造化データ、外部のプロフィール（Googleビジネスプロフィールなど）とそろえる。
  6. JavaScriptを動かさないと本文が出ないページは、サーバー側で本文を出す形にする（クローラーがJavaScriptを動かすかは公開されていないため）。

Nurevoが日本の地域事業者62件で行った調査では、サイトの中のAEO対策を測るスコアと、Perplexityに名前を挙げられる・引用される割合の間に、関係は見られませんでした（調査の詳細）。構造化データやllms.txtは、読める状態にするための土台で、それだけで引用が増えると考えないほうが安全です。

WordPressでの手順

WordPressは、サイトの直下に robots.txt のファイルがない場合、WordPress自身が robots.txt を作って返します（仮想の robots.txt）。プラグインで追加する決まりは、この仮想の robots.txt に入ります。サーバーに robots.txt のファイルを置いていると、そちらが優先され、プラグインの設定は反映されません。

  1. ブラウザで https://自社のドメイン/robots.txt を開き、PerplexityBot と Perplexity-User の行があるか、User-agent: * で全体を Disallow にしていないかを見る。
  2. Nurevo AEO（無料）を入れると、AI検索のクローラーを仮想の robots.txt で許可する設定で、PerplexityBot と Perplexity-User（ChatGPT・Claudeの検索用クローラーも）を許可する行が入ります。サイトで使っている /wp-admin/ などの決まりは、そのグループにも書き直されます。AIの学習用クローラーは、初期設定では変えません。
  3. サーバーに robots.txt のファイルがある場合は、そのファイルに上の例の行を足すか、ファイルを消して仮想の robots.txt を使う（消す前に中身を控える）。
  4. セキュリティ用のプラグインやレンタルサーバーのWAF、CDNで、ボットや海外のIPを止めていないかを確かめる。止めているなら、Perplexityが公開しているIP範囲を許可に足す。
  5. 本文：答えになる事実を固定ページの文字で書く。Nurevo AEOは店舗・会社・サービスの事実を構造化データとllms.txtに出しますが、本文に書いていない事実を足すものではありません。
  6. 下のコマンドで、robots.txt と、PerplexityBot を名乗ったアクセスへの応答を確かめる。
# 1) robots.txt に2つのクローラーの行があるか
curl -s https://example.jp/robots.txt | grep -i -A3 perplexity

# 2) PerplexityBot を名乗ったアクセスが 200 で返るか（403・503・確認画面は要注意）
curl -s -o /dev/null -w "%{http_code}\n" \
  -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko; compatible; PerplexityBot/1.0; +https://perplexity.ai/perplexitybot)" \
  https://example.jp/

# 3) アクセスログで実際に来ているか（ログの場所はサーバーによって違う）
grep -E "PerplexityBot|Perplexity-User" access.log | tail -20

2つ目のコマンドは「名前で止めていないか」だけを確かめるものです。IP範囲で許可・拒否する設定の確認にはならないので、本当に来ているかは3つ目のアクセスログで見ます。ログに PerplexityBot が来ていて 403 や 503 が返っていれば、WAFなどで止まっています。

引用されているかの確かめ方

Perplexityの回答は聞くたびに変わるため、1回聞いて出た・出なかったで判断しないでください。次の3つを組み合わせます。

方法分かること分からないこと・注意
手で聞いて記録する社名を入れない質問（「◯◯市 歯科 土曜」など）で、名前が出たか、出典の一覧に自社のURLがあるか、何番目か1回では偶然が大きい。同じ質問を日を変えて複数回聞き、ログインの有無や地域の設定もそろえる
アクセス解析の参照元回答のリンクから来た訪問（参照元に perplexity.ai などが残る場合）リンクをクリックされなかった引用や、名前だけの登場は分からない。アプリによっては参照元が残らないことがある
サーバーのアクセスログPerplexityBot・Perplexity-User が来ているか、どのページを読んだか、エラーになっていないか読まれたことと、回答に使われたことは別

社名を入れた質問（「◯◯歯科の土曜の診療時間は？」）は、事実を正しく読めているかの確認に使い、登場率の計算からは外します。社名を入れると出るのが当たり前で、新しいお客様が実際に聞く質問とは違うためです。

Nurevo AEO の無料プランとStandardでは、月に1回、業種と地域から作った社名なしの質問3つをNurevoのサービスがPerplexityに聞き、名前が出たか・サイトが引用されたか・代わりに誰が出たかを管理画面に表示します（プラグイン自体はPerplexityに接続しません）。Pro（月14,800円〜、ベータ）では、最大20の質問を1〜3回ずつ聞き、競合のドメインと引用の回数を比べます。出典の順番はPerplexityが返した出典一覧の順で、検索順位やおすすめの順位ではありません。失敗した回は分母に入れず、回答が2件未満のときは率を出しません。

チェックリスト

  1. robots.txt に PerplexityBot と Perplexity-User を止める行がない（User-agent: * の Disallow: / も含めて）
  2. 個別のグループを作った場合、/wp-admin/ など全体の決まりもそのグループに書いた
  3. WAF・CDN・セキュリティ用プラグインで、Perplexityの公開IP範囲を止めていない
  4. PerplexityBot を名乗ったアクセスに 200 が返る
  5. アクセスログに PerplexityBot が来ていて、エラーになっていない
  6. 答えになる事実（料金・時間・地域・対象）が本文の文字にある
  7. 数字に時点と、他社の数字なら出典がある
  8. 社名・所在地・連絡先が、サイト内と外部のプロフィールでそろっている
  9. 社名なしの質問を決め、同じ条件で複数回聞いて記録している
  10. 設定を変えた日を記録し、最大24時間後以降に確かめている

よくある質問

PerplexityBot を許可すれば、Perplexityに引用されますか？

引用されるとは限りません。許可は読まれるための前提で、どのページを出典にするかはPerplexityが決め、その基準は公開されていません。

robots.txt で Perplexity-User を Disallow にすれば、読まれなくなりますか？

Perplexityの資料では、Perplexity-User はユーザーが求めた取得なので robots.txt の決まりを一般に無視するとされています。止めたい場合は、WAFでユーザーエージェントとIP範囲を見て止める方法を検討してください。

Perplexityは読んだページをAIの学習に使いますか？

Perplexityの資料では、PerplexityBot も Perplexity-User も、AIの基盤モデルの学習のためにコンテンツを集めるものではないと説明されています。

robots.txt を直したら、すぐ反映されますか？

Perplexityの資料では、変更が反映されるまで最大24時間かかることがあるとされています。確かめるのは翌日以降にしてください。回答に出るかどうかは、また別の話です。

Perplexityで有料版を使うと、出典が変わりますか？

プランやモードで回答の作り方が違う可能性はありますが、出典の選び方の違いは公開されていません。記録するときは、プラン・モード・ログインの有無をそろえてください。

llms.txt を置くとPerplexityに引用されやすくなりますか？

Perplexityがサイトの llms.txt を出典選びに使うという公式の説明は見つかりませんでした。置く場合は、主なページへの入口と事実の要約として扱ってください。詳しくはllms.txtのガイドにあります。

Perplexityが自社について間違ったことを答えます。どうすればいいですか？

回答の出典をたどり、自社サイトの古い記述なら直し、他のサイトの記述なら掲載元に更新を頼みます。AIの回答そのものを直接書き換えることはできず、反映までの時間も決まっていません。

AIが自社サイトを読めるか確かめる

無料チェックは登録不要です。URLを入れると、AIクローラーの許可、構造化データ、llms.txtの状態が分かります。WordPressなら無料のプラグインで、PerplexityBot と Perplexity-User を許可する設定と、事業の事実の構造化データをまとめて整えられます。
