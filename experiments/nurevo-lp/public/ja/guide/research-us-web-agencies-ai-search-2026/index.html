米国のWeb制作会社の自社サイト4,472件に見るAI検索への対応（2026年11月）

米国のWeb制作会社の自社サイト4,472件のトップページ・robots.txt・llms.txt を調べたところ、llms.txt があったのは23.1%（1,032件）で、日本の13.4%より高く、英国（21.5%）・カナダ（22.9%）・豪州（24.3%）と同じくらいでした。AI学習用のボットを robots.txt でブロックしていたのは4.3%で、GPTBot をブロックしていた128件のうち119件は、ChatGPT の検索用ボット（OAI-SearchBot）をブロックしていませんでした。

公開：2026年11月17日。データ：2026年11月12日集計。調査・執筆：Nurevo AEO（Bestie.合同会社）。Nurevo はAI検索対策（AEO）のツールと WordPress プラグインを提供しており、この分野に利害があります。国別レポートの1本目です。

要点

  1. 米国のWeb制作会社の自社サイト4,472件のうち、llms.txt があったのは23.1%（1,032件）。日本（13.4%、2,486件中333件）より約10ポイント高く、統計的にもはっきりした差でした（p<0.001）。トップページが HTTP 202 を返した671件を除くと27.2%です。
  2. JSON-LD（構造化データ）は米国69.0%・日本69.4%でほぼ同じ。一方、AI検索に関わる6項目をすべて満たすサイトは米国18.9%（846件）で、日本（10.4%）の約1.8倍でした。
  3. robots.txt があるサイト3,404件のうち、AIボットをブロックしていたのは4.3%（147件、日本1.3%）。ブロックされていたのは CCBot・Bytespider（各4.1%）、GPTBot（3.8%）など学習用のボットが中心で、OAI-SearchBot・Claude-SearchBot・PerplexityBot といった検索用のボットは各0.3%（9〜11件）でした。

調査概要

  1. 対象：Web制作会社の自社サイト。当社の収集リストで国が米国となっている制作会社サイト6,646件のうち、トップページに到達できた4,472件です。一般企業のサイト全体ではありません。比較には同じ調査の日本（2,486件）・英国（942件）・カナダ（908件）・豪州（1,719件）、米国以外の海外（8,880件）を使いました。
  2. 取得したもの：各サイトのトップページ、/robots.txt、/llms.txt、/llms-full.txt を1回ずつ（User-Agent：NurevoSurvey/1.0）。2026年11月上旬〜12日に取得し、11月12日に集計しました。
  3. 判定方法：llms.txt は、ステータス200で中身がHTMLではなく20文字を超えるテキストを「あり」としました。JSON-LD はトップページにあるかどうか、Organization系は @type に Organization・LocalBusiness・Corporation・ProfessionalService を含むもの。WordPress はトップページのHTMLに wp-content/・wp-includes/、または generator の WordPress 表記があるもの。SEOプラグインはトップページのHTMLの文字列で判定しました。
  4. AIボットのブロック：robots.txt で、各ボットに当てはまるグループの規則がトップページ（/）を Disallow にするか（最長一致）で判定しました。分母は robots.txt があるサイトです。「AIボットをブロック」は GPTBot・ClaudeBot・PerplexityBot・Google-Extended・CCBot・OAI-SearchBot のどれかをブロックしているものです。
  5. 「6項目」は、(1) llms.txt がある、(2) JSON-LD がある、(3) Organization または LocalBusiness の型がある、(4) robots.txt があり GPTBot・ClaudeBot・PerplexityBot・OAI-SearchBot のどれもブロックしていない、(5) meta description がある、(6) canonical がある、のうち当てはまる数（0〜6）です。この調査のための単純な数で、Nurevo の0〜100点のスコアとは別物です。
  6. HTTP 202：米国では671件のトップページがステータス202を返しました（日本は0件）。これらのページには JSON-LD も WordPress の痕跡もなく、ボット確認などの別のページが返った可能性があります。そのため、202を除いた値も並べています。

結果：米国と日本・英語圏の比較

米国の値は、英国・カナダ・豪州とほぼ同じ水準でした。日本と比べると、llms.txt・FAQPage・「6項目すべて」が高く、meta description・canonical・robots.txt は低めです。ただし米国の低い項目は、202を返した671件（ほぼすべての項目が「なし」になる）の影響を受けています。202を除くと meta description 80.0%、canonical 87.4%、robots.txt 88.8% で、日本との差は小さくなります。

ボット別のブロック率

米国で robots.txt があるサイト3,404件について、ボットごとにトップページをブロックしている割合です。学習用とされるボット（CCBot・Bytespider・GPTBot・Google-Extended・ClaudeBot など）は3〜4%台、ユーザーの質問に答えるときや検索用に使われるボット（ChatGPT-User・OAI-SearchBot・Claude-SearchBot・PerplexityBot）は0.3〜0.4%でした。Googlebot をブロックしていたのは4件、Bingbot は5件です。

ブロックの中身（事実）

  1. GPTBot をブロックしていた128件のうち119件（93.0%）は、OAI-SearchBot をブロックしていませんでした。学習用のボットは止めて、検索用のボットは通している形です。
  2. 上の11種のAIボットのどれかをブロックしていた159件のうち93件（58.5%）は、GPTBot・ClaudeBot・anthropic-ai・Google-Extended・CCBot・Bytespider・Applebot-Extended の7つをまとめてブロックする同じ組み合わせでした。
  3. robots.txt でAIボットの名前を挙げていながら、どれもブロックしていないサイトが149件ありました（robots.txt があるサイトの4.4%）。名前を挙げて許可しているか、トップページ以外だけを止めているものです。
  4. AIボットをブロックしていた159件のうち55件（34.6%）には llms.txt もありました。

WordPress とSEOプラグイン

米国の制作会社サイトの74.5%（3,333件）が WordPress でした（202を除くと87.7%）。WordPress のサイトは llms.txt 30.1%、JSON-LD 91.4%、6項目の平均4.8 で、WordPress 以外（1,139件、うち671件が202）は llms.txt 2.5%、6項目の平均0.28 でした。SEOプラグインは Yoast SEO が56.4%、Rank Math が18.0%、AIOSEO が7.1%で、日本（AIOSEO 35.2%・Yoast 14.4%）とは順位が逆でした。

プラグイン別に llms.txt があった割合を見ると、AIOSEO 53.4%、Rank Math 38.2%、SEOPress 33.3%、Yoast SEO 28.0%、プラグインを検出できなかったサイト18.7%でした。この調査では llms.txt をプラグインで作ったのか手で置いたのかは見ていません。

6項目の分布

米国は「0項目」（22.1%）と「6項目すべて」（18.9%）の両方が日本より多く、二極に分かれていました。0項目の多くは202を返したサイトで、202を除くと0項目は8.8%です。日本は3〜4項目の層が厚く（合わせて30.7%）、6項目すべては10.4%でした。日本の5項目のサイトでは、欠けている項目の多くが llms.txt です（スコア分布の調査）。

限界

  1. 対象はWeb制作会社の自社サイトで、一般企業のサイト全体ではありません。国は当社の収集リストの記載によるもので、米国の制作会社全体を代表する標本ではありません。
  2. トップページだけを見ています。robots.txt はトップページ（/）に対する判定で、一部のディレクトリだけのブロックや、ファイアウォール・CDN によるブロックは数えていません。llms.txt は有無だけを見て、中身の質は見ていません。
  3. 各サイト1回の取得で、到達できなかったサイトは除いています。HTTP 202 を返した671件は、実際のトップページとは違うページを見ている可能性があります。
  4. SEOプラグインはHTMLの文字列による判定で、痕跡を消している場合や複数入っている場合は正しく分けられません。
  5. 今回の集計の一部には11月5日集計時の取得分を引き継いでいます。

当社の見方（意見）

ここからは事実ではなく当社の意見です。米国と日本の制作会社サイトは、構造化データの導入率はほぼ同じで、差が大きいのは llms.txt と、それを含めた「全部そろっているか」の部分でした。日本の制作会社にとっては、新しい対策を一から始めるより、すでにある構造化データに会社の事実を足し、llms.txt のような小さな抜けを埋めるほうが近道だと考えます。また米国のデータでは、学習用のボットは止めても検索用のボットは通すサイトがほとんどでした。どちらを止めるかは各社の判断ですが、AI検索に出たい場合は検索用のボットまで止めていないかを確かめる価値があります。どれを整えてもAIの回答に出ることが保証されるわけではありません（別の調査では、サイト側の項目と登場の間に関係は見られませんでした）。

自社やお客様のサイトを確かめる

無料チェックで、llms.txt・構造化データ・AIクローラーの許可状況を1分ほどで確認できます。WordPress なら Nurevo WebMCP プラグインで llms.txt を出し、会社の事実を構造化データに加えられます。お客様のサイトにまとめて入れたい制作会社の方はパートナー制度をご覧ください。

よくある質問

米国の制作会社は日本よりAI検索への対応が進んでいますか？

llms.txt（米国23.1%・日本13.4%）と「6項目すべて」（18.9%・10.4%）は米国が高く、JSON-LD は69.0%と69.4%でほぼ同じでした。meta description や canonical は日本のほうが高めです（2026年11月、Web制作会社の自社サイト）。

米国ではAIクローラーをブロックしているサイトが多いですか？

robots.txt があるサイトの4.3%で、日本（1.3%）よりは多いものの少数でした。ブロックの多くは学習用のボットで、検索用の OAI-SearchBot をブロックしていたのは0.3%です。

HTTP 202 とは何ですか？

米国の671件のトップページが返したステータスです。JSON-LD などが見つからず、ボット確認などの別のページが返った可能性があるため、除いた値も載せています。
