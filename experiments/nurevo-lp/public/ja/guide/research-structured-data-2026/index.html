構造化データの導入率・種類・壊れ率：Web制作会社サイト15,838件を調査（2026年11月）

日本と海外のWeb制作会社の自社サイト15,838件のトップページを調べたところ、構造化データ（JSON-LD）があったのは日本69.4%（2,486件中1,726件）、海外72.0%でした。FAQPage は日本3.9%・海外9.4%、LocalBusiness は5.4%・12.3%と、日本は会社の事実を細かく書く型が少なめです。JSON-LD があるサイトのうち、読み取れない（壊れた）JSON-LD を含むのは日本1.7%・海外1.8%でした。

公開：2026年11月13日。データ：2026年11月12日集計。調査・執筆：Nurevo AEO（Bestie.合同会社）。Nurevo はAI検索対策（AEO）のツールを提供しており、この分野に利害があります。

要点

  1. トップページに構造化データ（JSON-LD）がある制作会社サイトは、日本69.4%（1,726 / 2,486）、海外72.0%（9,615 / 13,352）。差は小さい一方、FAQPage は日本3.9%・海外9.4%、LocalBusiness は5.4%・12.3%、住所（PostalAddress）は16.4%・28.0%でした。
  2. JSON-LD があるサイトのうち、壊れた（JSON として読めない）JSON-LD を含むのは日本1.7%（29件）、海外1.8%（177件）。JSON-LD がすべて壊れていたのは日本9件・海外10件でした。
  3. 日本の WordPress サイトでは、SEOプラグインが検出されたサイトの92.5〜99.1%に JSON-LD がある一方、プラグインが検出されなかった1,115件では48.3%でした。WordPress 以外のサイトは日本28.3%・海外9.0%です。

調査概要

  1. 対象：Web制作会社の自社サイト。日本3,352件（制作会社であることを確認できたもの）と、海外20,335件、計23,687件。一般企業のサイト全体ではありません。
  2. 到達：トップページを取得できたのは15,838件（日本2,486件、海外13,352件）。結果はこの15,838件についての数字です。
  3. 取得したもの：各サイトのトップページ（あわせて /robots.txt、/llms.txt、/llms-full.txt）を1回ずつ（User-Agent：NurevoSurvey/1.0）。2026年11月上旬〜12日に取得し、11月12日に集計しました。
  4. 判定方法：トップページの <script type="application/ld+json"> をすべて JSON として解析し、@type を入れ子も含めて数えました。1つでも解析できないブロックがあれば「壊れたJSON-LDを含む」としています。Organization系は @type に Organization・LocalBusiness・Corporation・ProfessionalService を含むもの。microdata は itemtype に schema.org の URL があるもの。WordPress とSEOプラグインは、トップページのHTMLに残る文字列（wp-content、yoast、rank-math、aioseo など）で判定しました。
  5. 国は当社の収集リストでの所在国です。30件未満の区分は載せていません。

結果：日本と海外

JSON-LD の有無では日本と海外の差は2.6ポイントです。差が大きいのは中身で、住所・LocalBusiness・FAQPage・microdata はいずれも海外の方が1.7〜2.5倍多く見られました。

よく使われている型

日本も海外も WebSite・Organization・BreadcrumbList が上位です。WebPage・ImageObject は海外で多く、これは SEOプラグインが自動で出力する「グラフ」形式の構造化データの違いが表れているとみられます。会社の連絡先にあたる ContactPoint は日本6.5%・海外15.6%、口コミの評価（AggregateRating）は0.2%・6.2%でした。

壊れたJSON-LD

JSON-LD のブロック単位では、日本2,352個中34個（1.4%）、海外15,609個中193個（1.2%）が JSON として解析できませんでした。サイト単位では日本1.7%・海外1.8%で、JSON-LD がすべて壊れていて構造化データとして何も読めないサイトは日本9件（JSON-LDがあるサイトの0.5%）、海外10件（0.1%）でした。壊れたJSON-LDを含むサイトの多く（日本29件中20件、海外177件中167件）は、ほかに正しく読めるブロックも持っていました。

WordPress のサイトは JSON-LD がある割合が高く、海外では92.5%でした。WordPress 以外のサイトでは、日本28.3%・海外9.0%にとどまります。

この調査の限界

  1. トップページだけを見ています。下層ページ（会社概要、よくある質問など）に構造化データがあっても数えていません。
  2. JavaScript で後から入れる構造化データは、取得したHTMLに含まれないため数えていません。1サイトにつき記録した @type は最大40種類です。
  3. 「壊れた」は JSON として解析できないものだけです。必須項目の不足や、schema.org の仕様・Google のリッチリザルトの要件に合っているかは検証していません。
  4. SEOプラグインはHTMLに残る名前で判定しており、名前を出さない設定や、別のプラグイン・テーマが出力する構造化データは区別できません。
  5. 対象はWeb制作会社の自社サイトで、一般企業や店舗のサイト全体の傾向ではありません。制作会社のリストは当社が集めたもので、すべてを網羅していません。各サイト1回の取得で、到達できなかったサイトは含みません。

Nurevo の見方（意見）

ここからは事実ではなく当社の意見です。JSON-LD の有無だけを見ると日本と海外の差は小さく、多くは SEOプラグインが自動で出力しているものとみられます。差が出ているのは、住所・営業時間・よくある質問のように、会社ごとに中身を入れる必要がある型でした。構造化データがあっても AI の回答に必ず登場するわけではありませんが（当社の別の調査では、サイト側の対策と登場率の関係は見られませんでした）、会社の事実を機械が正しく読めるようにする基本として、自社とお客様のサイトで一度確認しておく価値はあると考えています。

自社サイト・お客様のサイトを確認するには

無料チェックで、構造化データ・llms.txt・AIクローラーの許可状況を1分で確認できます。WordPress なら Nurevo WebMCP プラグインで、SEOプラグインの出力と重複させずに会社情報の構造化データと llms.txt を出せます。お客様のサイトにまとめて導入したい制作会社の方はパートナープログラムをご覧ください。
