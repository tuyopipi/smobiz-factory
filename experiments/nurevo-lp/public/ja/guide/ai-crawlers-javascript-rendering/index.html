AIのクローラーはJavaScriptを読むのか：ChatGPTやPerplexityに見えている中身の確かめ方

ChatGPT・Claude・Perplexityがページを読むときは、JavaScriptを動かす前の「最初のHTML」だけを読むと考えて準備するのが安全です。2024年のVercelの集計と、2026年に行われた複数のテストでは、これらのクローラーやアシスタントはJavaScriptを実行していませんでした。Google（AI Overviews・AI Mode）は検索の仕組みでJavaScriptを処理しますが、ほかのAIに読まれたい事実（料金・営業時間・対応エリア・よくある質問の答え）は、最初のHTMLに文字で書いておいてください。この記事では、その確かめ方と、WordPressで事実がJavaScriptの奥に隠れやすい場所をまとめます。

作成日：2026年11月26日（JST）。対象は、自社サイトを運営している方、サイトを作る・保守する制作会社の方です。コマンドはパソコンの「ターミナル」で動くものですが、コマンドを使わない確かめ方も書いています。

AIの仕組みは各社が予告なく変えることがあり、ここで紹介するテストも、ある時点の結果です。AIの回答は日や聞き方によっても変わります。最初のHTMLに事実を書くことは読まれるための前提で、AIの回答に出ることを保証するものではありません。

よく読まれている記事と、足りないこと

「AIクローラー JavaScript」「do AI crawlers render JavaScript」などで上位に出る日本語4本・英語8本を、2026年11月26日に読みました。日本語は、Ahrefs（2026年9月28日）、Uravation（9月5日更新）、Web担当者Forum（Mozの翻訳）（6月29日）、Kinsta（6月15日）。英語は、Vercel、Hall、searchVIU（11月3日更新）、Advanced Web Ranking（8月20日）、Go Fish Digital（9月11日）、SearchEngineWorld、Writesonic、RESONEOのテストです。

「主なAIのクローラーはJavaScriptを実行しない」「大事な内容はサーバー側で出す」という結論はほぼ共通でした。一方で、次の点はあまり書かれていませんでした。

足りない点この記事で書いていること
多くの記事の根拠が2024年12月のVercelの集計1つだけ2026年の3つのテストと並べた表。テストどうしで結果が違う点も書く
Google（検索の索引）と、Geminiなどがその場でページを取りに行くときの違いが混ざっている「索引で読む」と「その場で取りに行く」を分けて説明
確かめ方が「ページのソースを見る」の一言だけcurl・ブラウザ・Search Console・アクセスログの4つの手順と、それぞれで分かること・分からないこと

答え：どのAIがJavaScriptを実行するか（分かっている範囲）

まず前提として、ページの「最初のHTML」とは、サーバーが最初に返す文字のことです。ブラウザはそのあとにJavaScriptを動かして、一覧を読み込んだり、口コミや地図を埋め込んだりします。JavaScriptを実行しないクローラーには、あとから足された部分は見えません。

OpenAIとPerplexityは、クローラーの名前と用途を公開しています（OpenAI：クローラー、Perplexity：クローラー）。ただ、これらは用途の説明で、JavaScriptを実行するかどうかを約束するものではない、とUravationは指摘しています（Uravation）。そのため、実際の動きは外部の集計やテストで見るしかありません。

AIVercel（2024年12月、クローラーの集計）2026年のテスト（その場でページを取りに行くとき）
ChatGPT（GPTBot・OAI-SearchBot・ChatGPT-User）実行しない。JavaScriptのファイルは要求の11.50%で取りに来るが、実行はしない3つのテストとも、最初のHTMLだけを読んだ
Claude（ClaudeBot など）実行しない。JavaScriptのファイルの取得は23.84%3つのテストとも、最初のHTMLだけを読んだ
Perplexity（PerplexityBot など）実行しないSearchEngineWorld では最初のHTMLの値を答えた。RESONEO では要求がうまく取れず判定できなかった
Gemini・GoogleGooglebotの仕組みを使うため、JavaScriptまで処理するGeminiがその場で取りに行くときは最初のHTMLだけを読んだ（3つのテスト）。RESONEOは、AI Modeはその場で取りに来ず索引を使う、と記録から推定
Microsoft Copilot（調べていない）テストで結果が分かれた。スクリプトを取得しても実行しなかった例と、実行した例がある
Grok（調べていない）実行した記録はあるが、答えには最初のHTMLの値を使った例もある

出典：Vercel（2024年12月17日）、SearchEngineWorld（2026年6月9日、12のアシスタントを1回ずつ）、Writesonic（2026年3月、6つのアシスタント）、RESONEO（2026年1月）。SearchEngineWorld のテストでは、DeepSeek・ERNIE・Qwen・Kimi・Mistral の5つはJavaScriptを実行した値を答えています。どのテストも、ページ1つ・ある時点のもので、各社が仕組みを変えれば結果も変わります。

Googleは、生成AIの機能のためのガイドで、ブロックされていなければJavaScriptも処理すると説明しています（Google：生成AI機能のためのサイトの最適化、2026年7月10日）。Googleの検索では、JavaScriptの処理は「クロール」「レンダリング」「インデックス」の流れで行われます（Google：JavaScript SEOの基本）。つまり、Googleの索引に入ったページはJavaScriptのあとの中身で読まれる可能性がありますが、ChatGPTやClaude、Perplexityには同じことは期待できません。

確かめる手順1：コマンドで最初のHTMLを見る

いちばん確実なのは、サーバーが最初に返すHTMLを保存して、AIに答えてほしい事実の文字を探すことです。curl はJavaScriptを実行しないので、JavaScriptを実行しないクローラーに近い見え方になります。料金・サービス・よくある質問・アクセスなど、引用されてほしいページで試してください。

# 1) 最初に返るHTML（JavaScriptを動かす前）を保存する
URL="https://example.com/price/"
curl -sS -L --compressed -o initial.html \
  -w 'status=%{http_code} final=%{url_effective}\n' "$URL"

# 2) AIに答えてほしい事実が、そのHTMLに文字で入っているか
for WORD in "3,300円" "火曜定休" "03-1234-5678" "駐車場"; do
  if grep -qF "$WORD" initial.html; then echo "あり  $WORD"; else echo "なし  $WORD"; fi
done

# 3) 構造化データ（JSON-LD）が最初のHTMLに入っているか（0なら入っていない）
grep -o 'application/ld+json' initial.html | wc -l

# 4) AIのクローラーの名前で取りに行っても、同じ事実が返るか（手がかり）
for UA in "ChatGPT-User/1.0" "OAI-SearchBot/1.0" "Claude-User/1.0" "PerplexityBot/1.0"; do
  printf '%-20s ' "$UA"
  curl -sS -L --compressed -A "$UA" "$URL" | grep -cF "3,300円"
done

2で「なし」と出た事実は、JavaScriptであとから足されているか、画像の中の文字になっているか、別のページにあります。数字が <span> などのタグで分かれていると見つからないことがあるので、短い文字（「3,300」だけなど）でも探してください。

4は手がかりです。名前だけを名乗った要求は本物のクローラーとは違うIPアドレスから来るので、サーバーやCDNの扱いが変わることがあります。ここで 403 や別の中身が返る場合は、ボット対策の層を確かめます（CloudflareやWAFがAIのクローラーを止めていないか確かめる手順）。

確かめる手順2：コマンドを使わない方法

  1. ページのソースを見る：Chromeでページを開き、右クリックの「ページのソースを表示」（Windowsは Ctrl＋U、Macは Option＋Command＋U）。開いた画面で Ctrl＋F（Command＋F）を押し、料金や電話番号を探します。ここに出るのが最初のHTMLです。右クリックの「検証」で見える画面は、JavaScriptのあとの中身なので、比べる相手にはなりません。
  2. JavaScriptを止めて開く：検証の画面（デベロッパーツール）を開いたまま、Ctrl＋Shift＋P（Command＋Shift＋P）で「Disable JavaScript」と入力して選び、ページを読み込み直します。消えた一覧・口コミ・地図・数字が、JavaScriptで足されている部分です。終わったら同じ手順で「Enable JavaScript」に戻します。
  3. Googleの見え方は別に見る：Search Console の「URL検査」で「公開URLをテスト」を押し、「テスト済みのページを表示」からHTMLを見ると、Googleが処理したあとの中身が分かります。これはGoogleの見え方で、ほかのAIの見え方ではありません。
  4. AIに貼って聞くのは最後の確認に：AIにURLを貼って要約させる方法は手軽ですが、AIの説明は当てになりません。SearchEngineWorld のテストでは、Perplexity は「ページにアクセスできなかった」と答えた一方、テスト用のサーバーには正常に取得した記録（HTTP 200）が残っていました（SearchEngineWorld）。

確かめる手順3：アクセスログで実際の取得を見る

サーバーのアクセスログが見られるなら、AIのクローラーが実際にどのURLを取りに来たかを数えます。レンタルサーバーの多くは管理画面からログを取り出せます。

# サーバーのアクセスログで、AIのクローラーが何を取りに来たかを見る
# （combined形式のログで、7列目がURLの場合）
# （ページのあとに .js や /wp-json/ を取りに来ていても、実行した証拠にはなりません）
grep -E 'ChatGPT-User|OAI-SearchBot|Claude-User|Claude-SearchBot|Perplexity-User|PerplexityBot' access.log \
  | awk '{print $7}' | sort | uniq -c | sort -rn | head -30

ページのあとに .js のファイルを取りに来ていても、それだけでは実行した証拠になりません。Vercelの集計でも、ChatGPTとClaudeのクローラーはJavaScriptのファイルを取得していましたが、実行はしていませんでした（Vercel）。ログで分かるのは「来たか」「どのURLに何を返したか」までです。

WordPressで事実がJavaScriptの奥に隠れやすい場所

WordPressは、投稿や固定ページの本文をサーバー側（PHP）でHTMLにして返すので、ふつうに書いた本文は最初のHTMLに入ります。危ないのは、プラグインやウィジェット、外部サービスの埋め込みで後から足される部分です。次の表を、自分のサイトで上の手順を使って1つずつ確かめてください。

場所起きやすいこと直し方
タブ・アコーディオン（よくある質問の開閉など）多くは本文がHTMLに入っていて、CSSで隠しているだけ。ボタンを押してから読み込む作りだと入らないソースに答えの文字があるか確かめる。WordPressの「詳細」ブロックは開閉してもHTMLに本文が入る
「もっと見る」・無限スクロール・絞り込みで出る一覧（料金表・メニュー・物件・施工事例）最初の数件しかHTMLに入らず、残りは後から読み込む大事な料金や条件は、一覧とは別に本文の表で書く。一覧はページ送りのURLでも見られるようにする
口コミ・Instagram・Googleマップ・予約システムの埋め込み外部のスクリプトや iframe で表示され、自分のページの本文にならない営業時間・住所・予約の決まりなど要点を、本文に文字で書く（予約ページの作り方）
Googleタグマネージャーで入れた構造化データ（JSON-LD）JavaScriptで足されるので、最初のHTMLには入らないテーマやSEOプラグイン、構造化データのプラグインでサーバー側から出す
数字が増えていくカウンター、スライダー、ポップアップの中の文字作りによって、最初のHTMLの値が「0」だったり、文字が入っていなかったりする手順1で数字を探す。入っていなければ、同じ事実を本文に書く
CSSの ::before・::after で出している文字、画像の中の文字（バナーの料金など）JavaScriptとは別の理由で、文字として読まれにくい。Writesonicのテストでは ::before・::after の文字は6つのAIのどれにも読まれなかった料金・条件は本文のテキストで書き、画像には説明の代替テキストを付ける
ヘッドレス（WordPressをデータの置き場にして、表側をReactやNext.jsで作る）表側の作りが画面をブラウザで組み立てる方式だと、最初のHTMLがほぼ空になるサーバー側での描画（SSR）か、事前に作るHTML（SSG）にする。Vercelも大事な内容はサーバー側で描画するよう勧めている
ボット対策の「JavaScriptで確かめる」画面（CDNやセキュリティプラグイン）クローラーには確認画面しか見えないAI検索のクローラーへの扱いを確かめる（確かめる手順）

隠した文字の扱いについて、Writesonicのテストでは、CSSの display:none で隠した文字は6つのうち5つのAIが読んでいました（Writesonic）。開閉する作り自体が悪いわけではなく、答えの文字がHTMLに入っているかどうかが分かれ目です。

直し方の順番

  1. AIに答えてほしい事実を決める：料金（税込み）、営業時間と定休日、対応エリア、よくある質問の答え、会社の基本情報など、ページごとに5〜10個。
  2. 手順1か2で、その事実が最初のHTMLにあるかを確かめる。なければ、まず本文に文字で書く。いちばん簡単で、どのAIにも効く直し方です。
  3. 構造化データとllms.txtを、サーバー側で出す設定にする。タグマネージャーで足している場合は、テーマやプラグインに移す。
  4. 埋め込みや一覧は残してよいので、その要点を本文に書き足す。ボットにだけ別の中身を返す作りは、人とAIで内容がずれる原因になるので避け、誰にも同じHTMLを返す。
  5. ヘッドレスやJavaScriptで画面を組み立てるサイトは、制作会社と、サーバー側の描画か事前に作るHTMLに変えられるかを相談する。
  6. 直したら、手順1〜3をもう一度行い、何を直したかと日付を記録する。AIでの登場の変化は、同じ質問で測り直す（AIでの登場率の測り方）。

よくある質問

Google の AI Overviews や AI Mode は、JavaScriptで出した内容も読みますか？

Googleは、ブロックされていなければJavaScriptも処理すると説明しています。ただし、ChatGPT・Claude・Perplexity には同じことは期待できないので、大事な事実は最初のHTMLにも書いておくのが安全です。

アコーディオンで隠したよくある質問は、AIに読まれませんか？

答えの文字がHTMLに入っていて、CSSで隠しているだけなら、読まれる可能性があります。ボタンを押してから読み込む作りだと入りません。ページのソースで答えの文字を探して確かめてください。

Googleタグマネージャーで入れた構造化データは無駄ですか？

JavaScriptを処理するGoogleには読まれることがありますが、JavaScriptを実行しないクローラーには届きません。テーマやプラグインでサーバー側から出す形に移すと、どちらにも届きます。

ページビルダーで作ったWordPressのサイトは大丈夫ですか？

ページビルダーの多くはサーバー側でHTMLを作るので、ふつうの文章や見出しは最初のHTMLに入ります。ただ、後から読み込むウィジェットや埋め込みもあるので、使っている部品ごとに手順1か2で確かめてください。

llms.txt を置けば、JavaScriptの問題は気にしなくてよいですか？

いいえ。llms.txt はサイトの案内として役立ちますが、AIが引用するのは多くの場合、個々のページです。ページ自体の最初のHTMLに事実があることが先です。

ChatGPT にURLを貼ったら、正しく要約されました。問題ありませんか？

1回うまくいっても、ほかのページや別の日に同じとは限りません。AIの説明とサーバーの記録が食い違った例もあるので、ページのソースやアクセスログで確かめるのが確実です。

最初のHTMLに事実を書けば、AIの回答に出ますか？

保証はできません。読まれるための前提が整うだけで、AIの回答は日や聞き方、ほかのサイトの情報によって変わります。直したあとは同じ質問で測り直してください。

AIに見えている中身を確かめる

無料のチェックは登録不要です。URLを入れると、構造化データ・llms.txt・AIのクローラーの扱いを確かめられます。WordPressなら、無料のプラグインで構造化データとllms.txtをサーバー側から出せます。
