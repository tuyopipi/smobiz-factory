飲食店のAI検索対策：メニュー・営業時間・予約・アレルギー情報をAIに正しく読ませる手順

飲食店・カフェ・バーのAI検索対策（AEO）は、メニューと税込価格、営業時間とラストオーダー、定休日、料理のジャンル、席や個室、予約の方法を、公式サイトに文字で書き、同じ内容を構造化データ（schema.orgのRestaurantなど）とGoogleビジネスプロフィールにそろえて出すことです。「駅の近くで22時以降も入れる個室のある居酒屋」のような質問に、AIが推測せずに答えられる材料を用意します。アレルギーの情報は、出すなら正確で最新に保てる範囲だけを、混入の可能性とあわせて書きます。

作成日：2026年11月3日（JST）。Google・schema.org・OpenAI・国税庁・消費者庁などの情報は、同日に各公式ページで確認したものです。

AIの回答は日や聞き方、聞く人の場所によって変わります。この記事の対策は、AIがお店の事実を正しく読める状態をつくるもので、AIの回答に必ず表示される・おすすめの上位に入ることを保証するものではありません。

お客さんがAIに聞く質問と、答えに必要な事実

飲食店を探す質問は、場所・時間・人数・目的・予算・食事の制限が一度に入るのが特徴です。AIはその条件を一つずつ確かめられる情報を探すので、お店がどの条件に当てはまるかを、文字で読める形にしておくことが出発点になります。質問の型ごとに、必要な事実と書く場所を整理すると次のとおりです。

質問の例は説明のために作ったものです。構造化データの項目名はschema.orgとGoogleのドキュメントによります（2026年11月3日確認）。
よくある質問の型答えに必要な事実書く場所
「◯◯駅の近くで今から入れる店」住所、最寄り駅からの徒歩分数、曜日ごとの営業時間、ラストオーダー、定休日店舗情報のページ本文、構造化データ（address・openingHoursSpecification）、Googleビジネスプロフィール
「接待に使える個室のある和食」料理のジャンル、個室の有無と人数、席数、雰囲気が分かる説明本文（席・個室の説明）、構造化データ（servesCuisine）

AIはどこからお店の情報を読んでいるか

飲食店について答えるとき、AIが読む情報は大きく分けて、お店の公式サイト、Googleビジネスプロフィール（Googleマップの店舗情報）、グルメサイトや予約サイト、口コミやSNS、ニュースやまとめ記事です。Googleは、ビジネスプロフィールがAIの回答とほかの検索結果の両方で見つけてもらう助けになるとしています。Google：生成AI機能向けの最適化ガイド

ChatGPTは、ウェブ検索を使うときにIPアドレスからおおよその位置を判断し、回答には出典のリンクと「Sources（情報源）」の一覧を付けます。OpenAI：Searching the web with ChatGPT。「近くの店」のような質問では、聞いた人の場所によって答えが変わるということです。自分で確かめるときは、お店の地域名を質問に入れると比べやすくなります。

どのAIも、どの情報をどれだけ重く見るかは公開していません。確かに言えるのは、公式サイト・ビジネスプロフィール・グルメサイトで営業時間や価格が食い違っていると、AIはどれが正しいか判断できず、古い情報や間違った情報を答えてしまう可能性がある、ということです。対策の中心は、公式サイトを「正しい情報の元」にして、ほかの場所をそれに合わせることです。

メニューは画像やPDFだけにせず、文字で載せる

メニューが写真やPDFだけだと、AIや検索エンジンが料理名と価格を正しく読み取れるとは限りません。公式サイトには、料理名・税込価格・簡単な説明を文字で書いたメニューのページを用意し、写真はそれに添えるのが確実です。季節で変わるメニューは「冬のコース（12月〜2月）」のように期間を書き、終わったものは消します。

価格は税込の総額で書きます。国税庁は、消費者に対してあらかじめ価格を表示する場合、表示する媒体を問わず消費税込みの総額を表示するよう定めています。国税庁：総額表示の義務。テイクアウトとイートインで税込価格が違う場合は、両方を書いておくと誤解されにくくなります。

Googleビジネスプロフィールには、飲食店向けのメニュー作成機能があり、セクション・料理名・価格・説明を入れられます。メニューのリンク（URL）は別の欄で設定します。Googleはお店のウェブサイトからメニューの情報を読み取って載せることがあり、間違っていれば編集・削除、または読み取りをやめる設定ができます。Googleビジネスプロフィール ヘルプ：メニュー エディタについて。公式サイトのメニューを正しく保つことが、ここでも効いてきます。

構造化データ：Restaurantに何を書くか

構造化データでは、お店をschema.orgのFoodEstablishmentの種類で表します。FoodEstablishmentはLocalBusinessの一種で、下にRestaurant、CafeOrCoffeeShop（カフェ）、BarOrPub（バー・居酒屋）、Bakery（パン屋）、FastFoodRestaurant、IceCreamShopなどがあります。Googleはローカルビジネスの構造化データで、できるだけ具体的な種類を使うよう案内しており、例にもRestaurantを使っています（2026年9月8日更新のドキュメントを11月3日に確認）。Google：ローカルビジネスの構造化データ

「Googleでの扱い」は、2026年11月3日に確認したGoogleのローカルビジネスのドキュメントによります。acceptsReservationsとhasMenuは、schema.orgのFoodEstablishmentで定義されている項目です。
項目書く内容Googleでの扱い
name / address店名（看板・ビジネスプロフィールと同じ表記）と住所必須
openingHoursSpecification曜日ごとの開店・閉店時刻。ランチとディナーで分かれる場合は2つに分ける推奨
telephone / url / geo電話番号、公式サイトのURL、緯度経度推奨
servesCuisine料理のジャンル（例：和食、イタリア料理、焼き鳥）推奨
menuメニューのページのURL（完全なURL）推奨
priceRange価格帯の目安（例：「¥3,000〜¥5,000」）。100文字未満推奨
acceptsReservations / hasMenu予約を受けるか（はい・いいえ、または予約ページのURL）／メニューそのものを構造化したものschema.orgの項目。Googleのドキュメントには載っていない

hasMenuを使うと、Menu・MenuSection・MenuItemで料理一つずつを構造化でき、schema.orgの例では食事制限（suitableForDiet）も書けます。ただし、Googleのドキュメントで推奨されているのはメニューのURL（menu）までです。料理一つずつの構造化は、メニューが頻繁に変わる店では更新漏れの原因にもなるので、まずは本文のメニューを正しく保つことを優先してください。

構造化データに書く値は、ページに見えている内容と同じにします。本文にない料理や、実際とは違う価格帯を構造化データだけに書くのはやめましょう。

アレルギー・食事制限の情報：AIに伝える前に決めておくこと

日本では、飲食店で提供する料理（外食）は、食品表示法によるアレルギー表示の義務の対象ではありません。そのうえで業界の手引きは、情報を出す場合は原材料を仕入れ先の規格書などで確認して最新に保つこと、同じ厨房で調理するため意図しない混入（コンタミネーション）の可能性があることを伝えること、正確な情報を把握できない場合は「提供しない」ことを事前に伝えることなどを求めています。ウェブサイトでの情報提供は来店前に確認できて便利な反面、更新を怠ると誤食の原因になるとも書かれています。外食・中食におけるアレルゲン情報の提供に向けた手引き（外食・中食産業等食品表示適正化推進協議会、2023年3月9日修正版）

AIは、サイトに書かれた文章を要約して答えます。「アレルギー対応」「グルテンフリーで安心」のような短い言葉だけを書くと、条件や例外が落ちたまま伝わるおそれがあります。書くなら、対応できる範囲（例：「卵・乳を使わない料理を3品ご用意しています」）、混入の可能性（「同じ厨房で卵・乳を扱っています」）、確認の方法（「ご予約時に電話でご相談ください」）を、同じ段落にまとめて書きます。対応できないなら、そう書くのも大切な情報です。

構造化データでは、確かめられないことを書かないのが原則です。schema.orgには食事制限を表す項目がありますが、混入の可能性を表せないため、アレルギーに関わる内容は本文で条件ごと説明するほうが安全です。

口コミとグルメサイト：AI向けにしてはいけないこと

自分のサイトに載せた口コミや星の評価を構造化データにしても、Googleの検索結果で星としては表示されません。Googleは2019年に、事業者についての口コミをその事業者自身のサイトに載せるもの（自己言及的なレビュー）は、LocalBusinessとOrganizationでは認めないとしています。Google検索セントラル ブログ（2019年9月16日）

日本では2023年10月1日から、ステルスマーケティングが景品表示法違反になりました。お店が第三者に依頼・指示して書かせた口コミや投稿は、そのお店の広告として扱われます。消費者庁：ステルスマーケティング。AIに良く書いてもらうために、広告であることを隠した口コミや「地域No.1」のような根拠のない表現を増やすのはやめましょう。

グルメサイトや予約サイトのページは、AIの出典として使われることがあります。自分で編集できるサイトは、公式サイトと同じ営業時間・価格・定休日に直し、編集できないサイトは運営会社に修正を依頼します。

WordPressの飲食店サイトでの設定手順

  1. WordPress.orgからNurevo AEO（無料）をインストールして有効化します。Yoast SEO・Rank Math・All in One SEO・SEO SIMPLE PACK・VK All in One Expansion Unitなどはそのまま使えます。
  2. 初回の設定ウィザードで「飲食店・カフェ」を選びます。業種はRestaurantになります。カフェ・バー・パン屋なら、設定画面の「業種（schema.org型）」をCafeOrCoffeeShop・BarOrPub・Bakeryにします。店名・住所・電話番号・営業時間・お店の説明を確認します。説明文には料理のジャンルと特徴（例：「炭火焼き鳥と日本酒の店。個室あり、最大12名」）を入れます。空欄の項目だけが既存の設定から補われ、入力済みの値は上書きされません。
  3. コース料理・宴会プラン・貸切プランなど、予約して申し込むものは、設定画面のサービスとして1つずつ登録します。名前・所要時間（分）・料金（数字だけ）・通貨（JPY）・カテゴリ・予約URL・説明を入れると、お店に紐づいたService（料金はOffer、予約URLは予約のアクション）として出力され、llms.txtにも1行ずつ載ります。
  4. 駐車場・子ども連れ・喫煙・持ち込み・キャンセルの扱いなど、実際によく聞かれることをよくある質問に入力し、FAQを見せたいページにNurevo FAQブロック（または[nurevo_faq]ショートコード）を置きます。
  5. AEOスコアの画面で診断を実行し、チェックリストに出た不足をワンクリック修正で直します。構造化データ・llms.txt・AIクローラの許可（OAI-SearchBot、PerplexityBot、Claude-SearchBotなど）は無料プランで出力されます。
  6. 外からどう見えるかを無料のAI可読性チェックで確認し、Googleビジネスプロフィールとグルメサイトの営業時間・価格と一致しているかを見直します。

現在のNurevo AEO（0.9.1）は、servesCuisine・menu（hasMenu）・acceptsReservationsを出力しません。料理のジャンルはお店の説明と本文に、メニューは文字で書いたメニューのページに書いておけば、AIは本文から読めます。構造化データにも入れたい場合は、テーマやほかの方法で追加してください（いずれもGoogleでは必須ではなく推奨の項目です）。SEOプラグインと一緒に使う場合、Nurevo AEOは2つ目の構造化データを出さず、足りない住所・電話番号・営業時間・Restaurantなどの種類・サービスだけを追加します。Yoast・Rank Math・AIOSEOに店舗情報を追加する方法

AIの回答が間違っていたときの直し方

  1. AIの回答に付いている出典のリンクを開き、間違った情報がどのページから来ているかを確かめます。
  2. 出典が公式サイトなら、本文と構造化データを直します。ビジネスプロフィールなら、Googleの管理画面で直します。
  3. 出典がグルメサイトやまとめ記事なら、自分で編集するか、運営者に修正を依頼します。閉店した旧店舗のページや古い移転前の情報が残っていないかも確かめます。
  4. 臨時休業・営業時間の変更・価格改定のときは、公式サイト・ビジネスプロフィール・グルメサイト・llms.txtを同じ日に更新します。
  5. 直したあとも、AIの回答にすぐ反映されるとは限りません。数日〜数週間あけて、同じ質問で確かめ直します。

公開前のチェックリスト

  1. メニューが文字で書かれ、料理名と税込価格が読める。季節メニューには期間が書かれている。
  2. 曜日ごとの営業時間・ラストオーダー・定休日が、公式サイト・ビジネスプロフィール・グルメサイトで一致している。
  3. 構造化データの種類がRestaurant・CafeOrCoffeeShop・BarOrPubなど実態に合ったもので、住所・電話番号・営業時間が入っている。
  4. 料理のジャンル、席数や個室、子ども連れ・喫煙などの条件が本文に書かれている。
  5. コース・宴会プランの内容・税込価格・時間・予約方法が書かれている。
  6. アレルギーの情報は、出すなら範囲・混入の可能性・確認方法を一緒に書いている。出さないならその旨を書いている。
  7. 自分のサイトの口コミを評価の構造化データにしていない。広告であることを隠した口コミを使っていない。
  8. llms.txtに、お店の概要・メニュー・アクセス・予約のページが載っている。llms.txtとは

AIに出ているかを確かめる

お客さんが聞きそうな質問を、地域・ジャンル・場面（ランチ、接待、子ども連れ、深夜など）の組み合わせで10個ほど決め、ChatGPT・Perplexity・GoogleのAI機能に聞いて、お店が名前やURLで出てくるか、営業時間や価格が正しいかを記録します。回答は回ごとに変わるので、同じ質問を期間をあけて繰り返します。やり方はAIでの登場率の測り方にまとめています。

Nurevo AEOでは、Free・Standardプランでも月に1回、業種と地域から作った3つの質問（店名は含めません）をPerplexityに投げ、回答にお店の名前やサイトが出たかを記録します。Proプラン（月14,800円〜）では、ベータ版のAI登場率の計測で、AIの回答にお店が出る割合を競合との比較・推移とあわせて見られます（現在の計測対象はPerplexity）。どちらも回答のサンプルを見るもので、すべての回答を観測するものではありません。

よくある質問

飲食店のAI検索対策は、何から始めればいいですか？

公式サイトに、メニュー（料理名と税込価格）・営業時間・ラストオーダー・定休日・住所・予約方法を文字で正しく書くことからです。次に、同じ内容をGoogleビジネスプロフィールとグルメサイトにそろえ、Restaurantなどの構造化データとllms.txtで公開します。

グルメサイトに載っていれば、公式サイトは要りませんか？

グルメサイトのページもAIの出典になりますが、公式サイトはお店がいちばん詳しく正しく情報を出せる場所で、ほかのサイトを直すときの基準にもなります。両方の値をそろえておくのが確実です。

メニューの写真を載せていれば十分ですか？

写真やPDFだけだと、料理名や価格が正しく読み取られるとは限りません。料理名・税込価格・説明を文字で書いたメニューのページを用意し、写真はそれに添えるのがおすすめです。

アレルギー対応をAIに伝えるべきですか？

正確で最新の情報を出し続けられる場合に限ります。日本では外食にアレルギー表示の義務はありませんが、出すなら対応範囲・混入の可能性・確認方法を一緒に書きます。把握しきれない場合は、提供していないことを書くのも大切です。

Nurevo AEOは無料で使えますか？

はい。業種（Restaurantなど）・住所・営業時間・コースなどのサービス・FAQの構造化データ、llms.txt、AIクローラ設定、AEOスコアは無料プランで使えます。有料プランは常に最新のルールセット（Standard、月3,000円）と、ベータ版のAI登場率の計測（Pro、月14,800円〜）を追加するものです。Nurevo AEO（WordPress.org）

対策すればChatGPTのおすすめに必ず入りますか？

いいえ。AIの回答は聞き方や聞く人の場所によって変わり、どのツールや対策でも表示や順位は保証できません。できるのは、お店の事実をAIが正しく読める状態にし、出ているか・正しく答えているかを続けて確かめることです。

まず、AIがお店のサイトをどう読んでいるか確認

登録不要の無料チェックで、構造化データ・llms.txt・AIクローラの状態がわかります。WordPressなら、Nurevo AEOで不足分を無料で整えられます。
