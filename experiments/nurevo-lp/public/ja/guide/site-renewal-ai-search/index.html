サイトリニューアルでAI検索の出典を失わない手順：制作会社が公開前・公開日・公開後にやること

リニューアルでAI検索の出典を失わないためには、①公開前に、AIの回答に引用されているURLと、構造化データ・llms.txt・robots.txtなどAI向けの出力を棚卸しし、②旧URLから新URLへ1対1のサーバー側の恒久的なリダイレクト（301か308）を用意し、③公開日に、新しいサーバーでAIのクローラーが止められていないか、構造化データやllms.txtに旧URLが残っていないかを確かめ、④同じ質問で前後を測ります。リダイレクトの決まりはGoogleが公開していますが、ChatGPT・Perplexity・Claudeがリダイレクトをどう扱うかの公式の説明は見つかりません。だからこそ、AIがどのURLを読みに来ても同じ事実にたどり着ける状態を、公開日に作っておくことが大切です。

作成日：2026年11月19日（JST）。対象は、お客様のサイトのリニューアル、テーマやCMSの入れ替え、常時SSL化、ドメイン変更、複数サイトの統合を請け負う制作会社・SEO会社・WordPress保守会社です。契約を終えて別の会社にサイトを渡す場合はAI検索対策の解約・引き継ぎの手順を、リニューアルの後にAIでの表示が落ちた原因を探す場合はAIでの表示が下がったときの原因を見てください。

AIの回答は日や聞き方によって変わります。この記事の手順は、リニューアルで引用されていたページや事実が消えたり食い違ったりしないようにするためのもので、リニューアル後もAIの回答に出ることや、出る日数を保証するものではありません。

よく読まれているリニューアルの記事と、足りないこと

「サイトリニューアル SEO」「サイトリニューアル AI検索」「website migration AI search」で上位に出る日本語5本と英語7本を、2026年11月19日に読みました（日本語のもう1本は取得できず）。301リダイレクトを使うこと、旧URLと新URLを1対1で対応させること、リダイレクトを1年以上残すことは、ほぼすべての記事が一致しています。一方で、次の点はほとんどの記事に書かれていませんでした。

記事ごとの良し悪しではなく、抜けやすい点をまとめています。Googleのリダイレクトの決まりは、日本語の記事でもよく整理されていました。
足りない点この記事で書いていること
日本語の記事の多くはGoogleの順位だけを扱い、AIのクローラー・llms.txt・構造化データに触れていない（触れていたのは1本）AI向けの出力を棚卸しの表に入れ、公開日に確かめる手順にした
英語の記事はAI検索を扱うが、WordPressでの手順がないWordPressでの作業（旧ドメインの置き換え、設定の移し方、仮想のrobots.txtと実ファイル）を書いた
構造化データは「引き継ぐ」とだけ書かれ、URLが入っている場所の話がない会社のURL・@id・サービスのURLなど、ドメインを変えると古くなる項目を挙げた
新しいサーバー・CDN・WAFでAIのクローラーが止められていないかを確かめる記事が少ない公開日の確認表に入れた
「AIが新しいURLを引用するまで◯週間」という数字が出典なし、または1社の自社データ日数は書かず、同じ質問で前後を測る方法を書いた

まず、変更の種類を分ける

Googleは「URLが変わるサイト移転」と「URLが変わらない移転（サーバーの引っ越しなど）」を分けて手順を書いています（Google 検索セントラル：サイトを移転する）。AI検索でも同じで、URLが変わるかどうかで作業の量が大きく変わります。

アドレス変更ツールの対象は、Search Consoleのヘルプによります（[アドレス変更ツール](https://support.google.com/webmasters/answer/9370220?hl=ja)）。http→https、サイト内のパスの変更、www の有無、URLが変わらないサーバーの変更には使いません。
変更例必要な作業アドレス変更ツール
URLは変わらないサーバーの引っ越し、テーマの入れ替え、デザインの変更リダイレクトは不要。新しいサーバー・テーマで構造化データ・robots.txt・llms.txt・本文の事実が同じか確かめる使わない
ページのURLが変わる/service.html → /services/、パーマリンクの変更URL対応表と1対1の301。内部リンク・サイトマップ・canonicalを新URLに使わない
http → https常時SSL化全URLを https へ301。混在がないか確かめる使わない
ドメインが変わるold-example.jp → example.jp、社名変更上のすべて＋旧ドメインを残して転送を続ける。構造化データ・llms.txtの会社のURLを直す使う（ドメイン・サブドメインの移転だけが対象）
サイトの統合店舗ごとのサイトを1つに残すページを決め、統合されるページを内容の近いページへ301。対応する内容がないページは404か410ドメインごと移すなら使う

Googleは「一度に1つだけ変える」ことを勧めています。デザインの刷新、URLの変更、ドメインの変更、本文の書き直しを同じ日に行うと、AIでの表示が変わったときに原因を切り分けられません。予算や日程の都合で一度に行う場合も、少なくとも「URLと本文の事実は同じ日に変えない」ように、作業の順番をお客様と決めておくと後で説明しやすくなります。

公開前①：AI検索に関わるものを棚卸しする

通常のリニューアルの棚卸しは、全URL・検索での流入・被リンクを集めます。Googleも、旧URLの一覧はサイトマップ・サーバーのログ・アナリティクス・Search Consoleのリンクのレポートから集めるよう書いています。AI検索のためには、これに次の行を足します。

AIへの質問の結果は日によって変わります。同じ質問を同じAIに、日を変えて2回以上聞き、両方を記録しておくと、公開後に比べやすくなります。
棚卸しするもの集め方なぜ要るか
AIの回答で引用されているURLお客様の業種・地域で実際に聞かれそうな質問を10〜20個決め、ChatGPT・Perplexity・GoogleのAIによる概要で聞き、出典に出たURLを記録する通常の流入の多いページと一致しないことがある。引用されているページは、対応表で必ず内容の同じページへ送る
AIからの流入があるページアナリティクスで、参照元が chatgpt.com・perplexity.ai などのセッションの入口ページ引用されたページのうち、人が実際にクリックしているもの
GoogleのAI機能での表示Search Consoleの生成AIパフォーマンスレポート（ヘルプ）でページごとの表示回数公開後に新しいプロパティで比べるための基準
構造化データ（JSON-LD）主なページのソースとリッチリザルトテスト。どのプラグイン・テーマ・コードが出しているかテーマやSEOプラグインを変えると、出す側が変わって消えたり二重になったりする
/llms.txt と /robots.txtブラウザで開いて保存。プラグインが返しているのか、サーバーに実ファイルを置いているのか新しいサーバーで実ファイルが置かれていない・古い実ファイルが残る、が起きやすい
事実の載ったページ料金・営業時間・所在地・対応エリア・会社概要・FAQのページのURLと、載っている値AIが答えに使う事実は、デザインを変えても値を変えない。変えるなら公開日とは別の日に

公開前②：URL対応表とリダイレクトを作る

リダイレクトの扱いは、Googleが詳しく公開しています（リダイレクトと Google 検索、サイトを移転する）。要点は次のとおりです。

  1. できるかぎりサーバー側の恒久的なリダイレクト（301か308）を使う。Googleは、301などの恒久的なリダイレクトでPageRankは失われないとしている。
  2. 302・303・307は一時的なリダイレクトとして扱われ、転送先を正規のURLとする手がかりにはならない。戻す予定がないなら恒久的なものを使う。JavaScriptでの転送は、サーバー側やメタリフレッシュができない場合だけ。
  3. 旧URLは、内容の対応する新URLへ直接送る。多くの旧URLを関係のないページ（トップページなど）にまとめて送ると、ソフト404として扱われることがある。
  4. 対応する内容がなくなったページは、404か410を返す。
  5. 転送を何段も重ねない。Googlebotは10回まで追うが、最終の転送先へ直接送ることを勧めている（できない場合も5回未満、できれば3回以下）。
  6. リダイレクトはできるだけ長く、一般に1年以上残す。新しいURLには自分自身を指す canonical を付け、内部リンク・サイトマップ・hreflang を新URLに直す。
  7. 移転中は順位が一時的に変動することがあり、中規模のサイトで新しいURLに入れ替わるまで数週間以上かかる。
# Apache（.htaccess）: ページのURLが変わったとき（1ページずつ、移転先へ直接）
Redirect 301 /service.html https://www.example.jp/services/
Redirect 301 /company/access.html https://www.example.jp/access/

# Apache: ドメインを変えたとき（パスは同じ）
RewriteEngine On
RewriteCond %{HTTP_HOST} ^(www\.)?old-example\.jp$ [NC]
RewriteRule ^(.*)$ https://www.example.jp/$1 [R=301,L]

# nginx: ドメインを変えたとき（旧ドメインの server ブロック）
return 301 https://www.example.jp$request_uri;

対応表には「旧URL・新URL・ステータス（301/404/410）・AIで引用されていたか・載っている事実」の列を作ります。AIで引用されていた行は、新URLの本文に同じ事実（料金・時間・住所など）が載っていることまで、行ごとに確かめます。

ChatGPT・Perplexity・Claudeについては、リダイレクトをどう扱い、旧URLの引用をいつ新URLに切り替えるかを説明した公式の資料は見つけられませんでした（2026年11月19日時点）。Googleの決まりに沿って1回の恒久的なリダイレクトにしておけば、どのAIのクローラーが旧URLを読みに来ても、同じ内容のページにたどり着けます。

公開日：AI検索のために追加で確かめること

通常の公開日の確認（noindex の外し忘れ、ステージングの robots.txt、計測タグ）に加えて、AI検索のために次を確かめます。

確かめること起きやすいこと確かめ方
robots.txt でAI検索のクローラーを止めていないかステージングで入れた Disallow: / がそのまま本番に出る。新しいサーバーに古い実ファイルの robots.txt が置かれるhttps://ドメイン/robots.txt を開き、OAI-SearchBot・PerplexityBot・Claude-SearchBot などの扱いが公開前と同じか見る
サーバー・CDN・WAFで止めていないか新しいサーバーや CDN のボット対策が初期設定で、AIのクローラーを止めるUA（名前）だけでなく各社が公開しているIPの範囲で許可する。Perplexityは、設定の反映に最大24時間かかることがあるとしている（Perplexity：クローラー）
構造化データに旧URLが残っていないか会社のURL・@id・ロゴ・サービスのURLが、手で入れた旧ドメインのままリッチリザルトテストで主なページを確かめ、ソースで旧ドメインを検索する
構造化データが二重・空になっていないか新しいテーマが自前の構造化データを出し、SEOプラグインと会社の情報が2つになる。逆に外したプラグインの分が消えるリッチリザルトテストで、会社・店舗の情報が1つにまとまっているか
llms.txt が新URLを指しているか手で置いた llms.txt が旧URLのまま残るhttps://ドメイン/llms.txt を開き、リンクが新URLか、リンク先が200を返すか
事実が変わっていないかデザインの作り直しで、営業時間の表や料金の注記が抜ける棚卸しの「事実の載ったページ」の値を、新しいページと1つずつ照らす

WordPressでの手順（Nurevo AEOを使っている場合）

WordPressのサイトでは、次の順番で進めると漏れが少なくなります。Nurevo AEO（WordPress.orgの無料プラグイン）を使っている場合の動きも合わせて書いておきます。

  1. 新しいサイトを別の環境で作る場合は、旧サイトで設定を書き出し（Nurevo AEOのメニューの「設定 › ツール」か wp nurevo export）、新しいサイトで読み込みます。事業の情報・FAQ・サービス・出力のオン・オフが移ります。キー・トークン・プラン・接続は入らないので、接続しているサイトは新しいサイトでつなぎ直します。ページごとの設定（llms.txt や構造化データから外したページ、ページ専用のFAQ）は書き出しに入らないので、データベースごと移さない場合は手で設定し直します。
  2. ドメインを変えたら、データベースに残る旧ドメインを wp search-replace で置き換えます。まず --dry-run で件数を見て、バックアップを取ってから実行します。
  3. Nurevo AEOの設定の「URL」が空欄なら、構造化データの会社のURL・@id と llms.txt の URL は、WordPressのサイトのアドレス（新しいドメイン）が自動で使われます。旧ドメインを手で入れていた場合は、そのまま旧ドメインが出続けるので、新しいドメインに直すか空欄にします。サービスに入れたURLと予約のURLも手で入れた値なので、1つずつ直します。
  4. Nurevo AEOの llms.txt のページの一覧は、公開中の固定ページ・投稿を更新の新しい順に最大30件、今のパーマリンクで作っています。パーマリンクを変えれば一覧も新しいURLになります。
  5. AIのクローラーの許可は、WordPressが自動で作る仮想の robots.txt に足しています。新しいサーバーのドキュメントルートに robots.txt の実ファイルがあると、そちらが返され、許可の行は出ません。実ファイルを使うなら、同じ内容をそのファイルに書きます。
  6. テーマやSEOプラグインを変える場合、Yoast SEO・Rank Math・All in One SEO・Slim SEO と一緒なら、Nurevo AEOはそれらの構造化データの中に足りない事実を足します。テーマが自前の構造化データを出す場合は、それと重ならないように自前のまとまりを出します。入れ替えた後にリッチリザルトテストで1つにまとまっているかを確かめてください。
# 1. 旧URLが1回で新URLへ恒久的に転送されるか（転送の回数とステータスを全部表示）
curl -sIL https://old-example.jp/service.html | grep -i -E "^HTTP|^location"

# 2. 新サイトのAI向けの出力
curl -s https://www.example.jp/robots.txt
curl -s https://www.example.jp/llms.txt | head -20
wp nurevo status

# 3. データベースに旧ドメインが残っていないか（まず --dry-run で件数だけ見る）
wp search-replace 'https://old-example.jp' 'https://www.example.jp' --dry-run

# 4. 公開前のサイトから設定を移す（キー・トークン・プランは入らない）
wp nurevo export --file=nurevo-settings.json   # 旧サイト・ステージングで
wp nurevo import nurevo-settings.json          # 新サイトで

curl -sIL の結果で、1行目が 301（または308）、次の location が新URL、最後が 200 になっていれば、1回の恒久的な転送です。302 や、location が2回以上出る場合は直します。なお、curl で UA を変えても、IPの範囲で判定するWAFの動きは確かめられません。WAFはサーバー・CDNの管理画面のログで、AIのクローラーが止められていないかを見ます。

公開後：前後を測り、旧ドメインを手放さない

いつ見るもの見方
公開日〜1週間旧URLのリダイレクト、404の増加、サーバーのログのAIのクローラー引用されていたURLの行から順に、転送先が200か確かめる。ログでAIのクローラーが403などで止められていないか
ドメイン変更の直後Search Consoleのアドレス変更ツール（ヘルプ）旧・新の両方のプロパティのオーナーであること、旧トップページから新トップページへの301が条件。180日間、新しいサイトのクロールが優先される
毎週〜毎月Search Consoleの検索パフォーマンスと生成AIパフォーマンスレポート（旧・新のプロパティ）旧の数字が減り、新の数字が増えていくか。公開前の同じ期間と比べる
公開前と同じ間隔で棚卸しで決めた10〜20の質問同じAI・同じ質問で、名前が出たか、出典が旧URL・新URL・他社のどれかを記録する。1回の結果で判断しない
1年以上旧ドメインの契約とリダイレクトGoogleはリダイレクトを一般に1年以上残すよう勧め、アドレス変更ツールのヘルプは旧ドメインを少なくとも1年は契約し続けることを勧めている

「AIが新しいURLを引用するまでの日数」を示す記事もありますが、私たちが確認できたのは、1社が自社の利用者のデータとして示した数字（MaxAEO）だけでした。お客様への説明には使わず、「同じ質問で測って記録する」と伝えるほうが確実です。

Nurevo AEOの無料のAIチェック（接続した無料・Standardのサイトで月1回、社名を入れない3問をPerplexityに聞く）とPro（ベータ版、最大20問、現在はPerplexityが対象）は、出典に自分のサイトのホストが入っているかで「引用」を数えます。ドメインを変えた直後は旧ドメインでの引用は自社として数えられないため、その期間は旧ドメインの引用を手で記録しておくと、前後を比べられます。測り方の全体はAIでの登場率の測り方にまとめています。

見積もりと契約に入れておくこと（制作会社向け）

  1. 作業範囲に「AI検索に関わるものの棚卸し（引用されているURL、構造化データ、llms.txt、robots.txt、事実の載ったページ）」と「URL対応表」を、別の行として入れる。デザインの作業に含めると、時間が足りなくなったときに真っ先に削られる。
  2. 公開後の確認期間（例：公開後1か月の転送とログの確認、3か月目の質問の記録）を決めて書く。
  3. 旧ドメインの契約を誰が、いつまで払うかを決める。転送を1年以上続けるには、旧ドメインとその転送の設定を残す必要がある。
  4. AIの回答は変わるため、リニューアル後にAIに出ることや順位は保証しないこと、前後の測り方と報告の形を書く。
  5. 料金・営業時間などの事実の変更は、お客様の確認を取ってから、公開日とは別の日に行うこと。

リニューアルの後も月額でAI検索対策を続ける場合の作業範囲はAI検索対策を月額サービスにする方法に、制作会社が自社ブランドでお客様に報告する仕組みはパートナープログラムにまとめています。

リニューアルのチェックリスト

  1. 変更の種類（URLが変わらない・パス・https・ドメイン・統合）を決め、一度に変えるものをお客様と決めた。
  2. AIの回答で引用されているURLと、事実の載ったページを棚卸しした。
  3. 公開前の基準として、決めた質問の結果と、Search Consoleの数字を記録した。
  4. 旧URLから新URLへの1対1の301（または308）を用意し、転送が1回で終わることを確かめた。
  5. 対応する内容のないページは404か410にし、トップページへのまとめての転送をしていない。
  6. 新しいサイトの robots.txt・サーバー・CDN・WAFで、AI検索のクローラーを止めていない。
  7. 構造化データ・llms.txtに旧URLが残っておらず、会社の情報が1つにまとまっている。
  8. 内部リンク・サイトマップ・canonical・hreflang を新URLにした。
  9. ドメインを変えた場合、アドレス変更ツールを使い、旧ドメインと転送を1年以上残す段取りをした。
  10. 公開後、同じ質問で前後を測り、旧ドメインでの引用も記録している。

よくある質問

リニューアルすると、AIの回答から自社のサイトは消えますか？

必ず消えるわけではありません。ただ、引用されていたURLが404になったり、事実の載った表が抜けたり、新しいサーバーでAIのクローラーが止められたりすると、出典として使われにくくなります。公開前の棚卸しと、公開日の確認で防げることがほとんどです。

301と302はAI検索でも違いますか？

Googleは、301・308を恒久的、302・303・307を一時的なリダイレクトとして扱うと公開しています。ChatGPT・Perplexity・Claudeの扱いを説明した公式の資料は見つかりませんでしたが、戻す予定のない移転は301か308にしておくのが確実です。

リダイレクトはいつまで残せばいいですか？

Googleは、できるだけ長く、一般に1年以上残すことを勧めています。ドメインを変えた場合のアドレス変更ツールのヘルプは、少なくとも180日、Google検索からの流入が残っていればそれより長く残し、旧ドメインは少なくとも1年は契約し続けることを勧めています。

llms.txtはリニューアルでどうすればいいですか？

手で置いたファイルなら、新URLに書き直すか、作り直します。Nurevo AEOのように自動で作る仕組みなら、新しいパーマリンクで作り直されますが、会社のURLなど手で入れた値は旧ドメインのまま残ることがあるので確かめます。

テーマを変えるだけでもAI検索に影響しますか？

URLが変わらなければリダイレクトは要りませんが、テーマが構造化データを出す・出さないが変わったり、営業時間や料金の表の作りが変わったりします。新しいテーマで構造化データと本文の事実が公開前と同じかを確かめてください。

公開後、AIが古いURLや古い情報を出し続けます。どうすればいいですか？

まず旧URLが1回の301で新URLに届くか、新しいページに同じ事実が載っているかを確かめます。そのうえで、同じ質問で日を変えて記録を続けます。AIの回答がいつ切り替わるかは公開されていないため、事実の側を正しく保つことがいちばん確実です。

サイトを統合するとき、統合される側のページはどうしますか？

内容の近いページがあれば、そのページへ301で送ります。対応する内容がなければ404か410を返します。関係のないページ（トップページなど）にまとめて送ると、Googleではソフト404として扱われることがあります。
