面向 AI 搜索的创始人、专家与作者介绍页：让 AI 正确读懂人物的职务、资质和专长

AI 能否正确回答关于某个人的问题，取决于这个人的介绍页是否用纯文本写明了他是谁、在哪里工作、擅长什么。把姓名、职务、所属机构、资质、专业领域和经历放在同一页上；从文章署名和公司简介页的管理层介绍链接到这一页；再把相同的值作为 Person 结构化数据发布。这三步是核心。夸大资质或虚构作者会适得其反：Google 把捏造的创作者资料称为欺骗。

本文撰写于 2026 年 11 月 16 日（日本时间）。当天核对了 Google 的《Creating helpful, reliable, people-first content》（创建有用、可靠、以人为本的内容，最后更新于 2026 年 10 月 5 日）和《Profile page (ProfilePage) structured data》（个人资料页结构化数据）。本指南面向设有创始人、院长、从业者、讲师或撰稿人介绍页的公司、店铺和诊所，以及为其建站的代理公司。公司本身的部分请参见公司简介页的 AI 搜索优化。

AI 的回答会因日期和措辞而变化。这些步骤能让 AI 读到的信息更准确，但不能保证某个人一定会出现在回答中，也不能保证排名上升。

AI 用人物介绍页来做什么

ChatGPT 搜索、Perplexity 和 Google 的 AI Overviews 在回答时会读取网页，并把它们列为来源。对于关于某个人的问题，此人所属机构网站上的介绍页是最直接的材料。如果没有这样的页面，或者页面上只有照片和姓名，或者各页面上的职务不一致，AI 就可能根据旧文章或同名的其他人来组织回答。

关于人物的问题大致可以分为几种类型。

  1. “Sample Ltd 的负责人是谁，有什么背景？”（创始人或 CEO）
  2. “Sample Clinic 的院长擅长什么？”（专家的资质和领域）
  3. “利兹哪位会计师擅长遗产税？”（按专长查找；问题中没有姓名）
  4. “这篇文章是谁写的，可信吗？”（作者）
  5. “Jane Doe 和 Sample Ltd 是什么关系？”（职务、其他职位、以前的工作）
  6. “怎样预约 Doe 医生的咨询？”（联系方式和预约）

像第三个这样不含姓名的问题，AI 会先寻找事务所或店铺，然后再补充由谁来负责。人物介绍页不仅在别人按姓名询问时是材料，在别人按专长搜索时也是。

关于作者信息和 E-E-A-T 的流行说法，很多都是猜测。请从 Google 自己写的内容出发。

为谁建页面，放在哪里

把网站上的人物分成四种角色。并不是每个人都需要很长的页面；从 AI 最可能被问到的人开始。

角色放在哪里最少内容如何关联
创始人或 CEO公司简介页内，或 /about/name/ 这样的页面姓名、职务、经历、在公司负责什么从公司简介页的管理层介绍链接过来；在标记中让公司的 founder 或 employee 指向同一个 @id
专家（院长、从业者、讲师）员工列表加上每人一页资质、登记号、领域、负责哪些服务从服务页的“由谁为您服务”处链接过来
文章作者WordPress 作者归档页或普通页面姓名、所属机构、主题、文章列表从署名链接过来
外部审核人审核人页面，并附上其所属机构的链接姓名、资质、所属机构、审核了什么在文章上写“审核：姓名（资质），日期”，并链接到该页面

同一个人同时是创始人、作者和审核人时，只保留一个页面，并在所有地方用相同的方式书写姓名和职务。两种写法可能会被 AI 当成两个人。

写什么，以及对应的结构化数据

下表列出了人物介绍页应包含的内容、AI 回答容易出现的错误，以及对应的 schema.org 属性，这些属性选自 Person 和 ProfilePage 的定义（类型依据 schema-dts 2.1.0 核对）。

项目写法AI 的典型错误结构化数据
姓名全站统一一种写法；其他文字写法或罗马字只给一次与同名者混淆name、alternateName
职务和所属机构一定带上公司名，例如“Sample Ltd 创始人”用以前的职务或副业头衔来介绍jobTitle、worksFor
资质正式全称、登记号（如可公开）、颁发机构、年份资质类型被混淆hasCredential（EducationalOccupationalCredential）
专业领域三到五个具体领域，而不是“什么都行”被推荐做领域之外的事knowsAbout
经历每行一个年份和事件：学历、以前的工作、何时创业年份混淆正文（学校用 alumniOf）
业绩数字附上日期和统计方法引用旧的或夸大的数字仅正文
获奖和媒体报道名称、年份、主办方；尽可能附链接把获奖和被提及混为一谈award（仅限获奖）
其他资料只列本人管理的账号被关联到冒充者或同名者sameAs
照片真实照片；不用 AI 生成的头像—image
文章和服务列表或链接不清楚此人从事什么领域正文
最后更新放在页面末尾；职务一变就立即修改用以前的职务来介绍dateModified（ProfilePage）

schema.org 对 knowsAbout 的描述是“suggesting possible expertise but not implying it”（暗示可能具备的专长，但并不意味着一定具备）（schema.org: knowsAbout）。只在标记中列出领域本身证明不了什么，因此要在正文中用处理过的案例和撰写的文章来佐证。

撰写页面：第一句就说明此人是谁

  1. 第一句写出姓名、职务、所属机构和领域，例如：“Jane Doe 是利兹 Sample Ltd 的创始人，也是一名专注于小企业账务和遗产税的特许会计师。”
  2. 第二句写能把她与他人区分开的事实：取得资质的年份、所属的协会、负责的地区。
  3. 资质要写全称。如果资质可以在公开名录中查到，可以注明，方便读者核实。
  4. 经历用表格或时间线呈现，而不是图片或 PDF。
  5. 把“业界第一”这类无法比较的说法换成事实：年数、数字、领域。
  6. 在医疗、法律等受监管的领域，对头衔和资质的宣传方式有相关规定。医疗领域另请参见诊所的 AI 搜索。

署名与审核人

在每篇文章的开头或结尾显示作者姓名，并链接到介绍页。用团队署名也可以，但团队页面应说明由谁、以何种方式撰写。

外部专家核对内容时，应称之为“审核”，与作者身份分开，并写明审核了什么（例如“税额计算部分”）以及何时审核。schema.org 有 reviewedBy，用于表示为页面准确性进行审核的人，这是与 author 不同的属性。不要把作者和审核人一起列在 author 下。

Google 建议向读者说明内容是如何制作的，包括是否使用了自动化或 AI。如果文章是用 AI 起草的，请在读者期待看到的地方说明这一点，并说明已经过人工核对。

标记示例：ProfilePage 与 Person

这是一个最简示例。每个值也都必须出现在正文中。让 worksFor 指向与公司节点相同的 @id，就能把人物和公司作为一对来读取。

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "ProfilePage",
  "dateModified": "2026-11-16",
  "mainEntity": {
    "@type": "Person",
    "@id": "https://example.com/about/jane-doe/#person",
    "name": "Jane Doe",
    "jobTitle": "Founder and Chartered Accountant",
    "worksFor": { "@id": "https://example.com/#organization" },
    "description": "Chartered accountant specialising in small-business accounts and inheritance tax in Leeds.",
    "knowsAbout": ["Inheritance tax", "Small-business accounting"],
    "hasCredential": {
      "@type": "EducationalOccupationalCredential",
      "name": "Chartered Accountant",
      "credentialCategory": "Professional qualification"
    },
    "image": "https://example.com/images/jane-doe.jpg",
    "sameAs": ["https://www.linkedin.com/in/example"]
  }
}
</script>

资质类型 EducationalOccupationalCredential 还可以写明资质的种类（credentialCategory）和认可该资质的机构（recognizedBy）。sameAs 中只放本人管理、且明确属于本人的资料。

// 2) 只在介绍页（slug 为 jane-doe）上加入 ProfilePage
add_filter('webmcp_canary_schema_graph', function (array $bundle) {
    if (!is_page('jane-doe')) {
        return $bundle;

    $bundle['extra'][] = array(
        '@type'      => 'ProfilePage',
        'url'        => get_permalink(),
        'mainEntity' => array(
            '@type'     => 'Person',
            '@id'       => home_url('/about/jane-doe/#person'),
            'name'      => 'Jane Doe',
            'jobTitle'  => 'Founder and Chartered Accountant',
            'worksFor'  => array('@id' => $bundle['org_id']),
            'knowsAbout'=> array('Inheritance tax', 'Small-business accounting'),
        ),
    );
    return $bundle;
});

如何检查：用带有人名的问题

用包含人名的问题来检查介绍页。在不同的日子向同一个 AI 提出同样的问题并记录回答；不要凭一次回答下结论。

记录内容示例
日期、AI、问题11 月 16 日，Perplexity，“Sample Ltd 创始人 Jane Doe 有什么背景？”
回答中的事实职务、资质、领域和经历：逐项判断对错
来源引用的是你的介绍页，还是别人的页面？
混淆回答中有没有同名者或以前的职务？

Nurevo 的免费 AI 检测（对已连接的 Free 和 Standard 网站每月一次）提出的问题是根据你的业务类型和区域生成的，从不包含人名，因此关于人物的问题需要用上表手动检查。Pro 的可见度测量（测试版）目前覆盖 Perplexity。完整方法见如何衡量 AI 可见度。

人物介绍页检查清单

  1. 第一句包含姓名、职务、所属机构和领域。
  2. 公司简介页、署名和员工页上的姓名和职务写法一致。
  3. 资质写了全称，并注明年份或颁发机构。
  4. 专业领域具体，并有案例或文章佐证。
  5. 数字附有日期，并说明统计方法。
  6. 没有虚构的人物、AI 生成的头像或夸大的资质。
  7. 署名链接到介绍页；审核与作者身份分开，并写明范围和日期。
  8. ProfilePage 和 Person 标记与正文一致，且没有重复。
  9. sameAs 只列出本人管理的账号。
  10. 职务一变就立即修改，最后更新日期也随之更新。
  11. 已在不同的日子用包含姓名的问题检查，并记录了结果。

常见问题

小公司也需要创始人介绍页吗？

在公司简介页中用几行写出姓名、职务和背景，通常就够了。如果创始人撰写文章、演讲或接受采访，或者有人按姓名搜索他，单独建一个页面可以把信息集中在一处。

没有正式资质的人写的文章，AI 会不太愿意使用吗？

Google 并没有说缺少资质本身是个问题。它说最重要的是信任，而以事实写出的真实经验（多少年、做过什么工作）就是很好的材料。对于健康或金钱相关话题，也可以请专家审核内容并加以说明。

可以用笔名发表吗？

可以，前提是不附加虚构的背景或资质，并且笔名的页面要说明此人以什么身份撰稿。Google 把捏造的创作者资料称为欺骗。

作者页和 ProfilePage 标记，哪个先做？

先做页面。标记是把与正文相同的事实转为机器可读的形式；不要在标记中放入正文没有写明的事实。

审核人应该放在 author 下吗？

把作者和审核人分开。schema.org 有 reviewedBy，用于表示核对页面准确性的人。正文中也请把“撰稿”和“审核”分开写。

我们的 CEO 换人了，应该更新哪些地方？

公司简介页、CEO 的介绍页、标记中的 founder 或 employee、署名，以及其他地方的资料（社交账号、行业名录）。保留前任 CEO 的页面并写明其职务和任期，或者把它指向新页面。AI 回答需要多久才能跟上，并没有固定的时间。

按这些步骤做了，AI 就一定能正确描述我们的人员吗？

无法保证；AI 的回答会因日期和措辞而变化。这些步骤能让 AI 读到的信息准确且一致，从而减少混淆。
